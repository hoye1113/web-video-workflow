## 0. 一句话

不再自己造视频工厂。**以 FRAMETELL 为唯一骨架**（流程、界面、检查器、时间轴都是它的），
把我们的三样东西以一等公民的身份装进去：**生成图 / 角色 IP / 情感风格包**。
它管流程和质量下限，我们管画面和 IP 上限。

## 3. 交付物与分工

### 3.1 三段分工

```
我们（系统出片）        →  剪辑人员（剪辑软件）        →  发布
干净母版 mp4              导入 SRT，调样式/位置/断句      平台/账号
字幕.srt（短句切分）      配乐、包装、片头片尾
口播脚本.md（对稿）       需要时导出最终成片
发布信息.md（标题/简介/标签/章节）
```

### 3.2 字幕：两种"字"，分工不同（**v2.1 新增，已定**）

| | 是什么 | 谁做 | 为什么 |
|---|---|---|---|
| **(a) 对白字幕** | 观众在底部看的字幕 | **剪辑软件**（我们只给 `.srt`） | 你说得对：那里调样式/位置/断句最快，也便于适配不同平台 |
| **(b) 屏上字 / 标签** | 画面里的字（「表面的和平」「规则」「边界」） | **我们**（属于画面） | 它是构图的一部分，跟着镜头动、和旁白的词对齐，不能外挂 |

**因此我们的出片默认不烧字幕**（`defaults.subtitles: false`），产出：

```
out/xxx-无字幕.mp4       干净母版 ← 给剪辑
out/字幕.srt             字幕文件 ← 导入剪辑软件（8-12 字一行）
out/口播脚本.md          带时间点的稿子 ← 对稿
out/xxx-有字幕.mp4       烧死版（需要直接发平台时才要）
```

**三条必须一起守的规矩：**

1. **短句切分**：它现在是一句一整行（最长 21 字）。短视频惯例 **8-12 字一行**，
   要加一道按标点优先的二次切分（我们的活）。
2. **字幕带继续留空**（画面下方 18%）：不是因为我们要烧字幕，而是因为
   **你/平台的字幕会落在那里**。检查照旧拦"屏上字进那条带"。
3. **断句取决于配音停顿**：它的 `narrate` 按"检测静音"把整段切回句子 →
   配音规范里加一条：**逗号/分句处稍作停顿**；配合二次切分，字幕就"一行一个意思"。

**另一个可用的路**：改了断句/错字后，用 `render.mjs --skip-video` **只重跑字幕**，不重渲画面。

## 9. 新机器的环境基线（照 README 做会断在哪）

README 只写了 **5 样**（node · pnpm · git · Chrome · ffmpeg），
新机器上实际要 **7 样 + bsk CLI**。完整推理与实测数据见 `docs/经验与坑.md` 第三批（卅二～卅八）；
这里只留**能直接照抄的安装顺序和判据**。

| # | 装什么 | 命令 / 判据 |
|---|---|---|
| 1 | git | 官方安装器 `/VERYSILENT /NORESTART` |
| 2 | node ≥ 22.19 | 官方 MSI：`msiexec /i node-*.msi /qn /norestart` |
| 3 | pnpm 10.5.2 | `corepack prepare pnpm@10.5.2 --activate` **＋ `corepack enable pnpm`**（**两句都要**）<br>判据：`C:\Program Files\nodejs\pnpm.cmd` 存在 |
| 4 | Python 3.12 | `python-3.12.10-amd64.exe /quiet InstallAllUsers=1 PrependPath=1` |
| 5 | uv | `python -m pip install --upgrade pip uv -i https://pypi.tuna.tsinghua.edu.cn/simple`<br>**别用 astral.sh 的安装脚本**（要回 GitHub） |
| 6 | edge-tts | `uv venv ~/.frametell/edge-venv` ＋ `uv pip install --python ~/.frametell/edge-venv/Scripts/python.exe edge-tts` |
| 7 | ffmpeg | 静态构建，`ffmpeg.exe`/`ffprobe.exe`/`ffplay.exe` 放 `~/.local/bin` |
| 8 | bsk CLI | 从 **GitHub API 按 asset id** 下（脚本见卅五），放 `~/.local/bin`<br>判据：`bsk --version` |

**装依赖前必须先设这一句**，否则 `pnpm install` 必挂：
```powershell
$env:FFMPEG_BINARIES_URL = 'https://registry.npmmirror.com/-/binary/ffmpeg-static'
```

**网络要分区对待**（别当成"GitHub 通不通"一个问题）：

| 域 | 行为 | 用途 |
|---|---|---|
| `api.github.com` | **稳定** | 所有 GitHub 读取（`/contents`、`/releases/assets/{id}`） |
| `github.com` | 时通时断（失败率约 2/3） | `git clone`/`push` **必须写重试** |
| `raw.githubusercontent.com` | 基本不通 | 别用 `irm … \| iex` 那类安装脚本 |

大文件走 `https://ghfast.top/https://github.com/...` —— 实测 **507 KB/s vs 直连 27 KB/s**。

**上机第一步就该跑的三条验证**（别靠印象）：
```powershell
bsk doctor                      # extension connected 必须是 ok
node apps/cli/dist/cli.js serve # 面板能不能起
git ls-remote origin            # 认证 + 网络是否都通
```

**用 bsk 驱动浏览器时的三条铁律**（都是实测出来的，见经验文档第五批）：

1. **开完会话第一条命令就是撑窗口**，而且要**撑得比屏幕大**
   （本机屏幕 1366×768，所以设 `1600x900`）——
   不然 Flow 这类响应式页面会把整排按钮折叠进 overflow，ARIA 树里都没有。
   ```powershell
   bsk window resize --session <sid> --width 1600 --height 900
   ```
2. **扩展按 Profile 隔离**：换账号/换 Profile 后必须重新确认扩展在不在
   （判据：那个 Profile 的 `Secure Preferences` 里有没有扩展 ID）。
3. **Flow 的地区判定分两层**：文档层看 IP、应用层看账号；
   命令行 curl 200 **不等于**账号能用，必须用带登录态的浏览器验。
