## 第一优先：逐页路由 + Flow 生图当主画面

### 为什么转这个向

实测摆在这里：

| | 代码画 | Flow 生图 |
|---|---|---|
| 质量 | 第 02 页迭代三轮提示词才到 6/10，评审还在挑 | **那只手一次到位**，风格和画风锁完全对上 |
| 耗时 | 一页 2-4 分钟（输出 6000-9000 字） | 一次提示词出 2 张，约 1 分钟 |
| 用户判断 | 「效果不好看」 | —— |

**根因不是模型不够强，是任务选错了。** 让模型用代码去「画」一个东西（纸张质感、
光影、手）是最难的部分；而代码真正擅长的是**让已经画好的东西动起来**。

### 一、三种片型（同一套引擎，三种走法）

| 片型 | 画面谁做 | 什么时候走这条 |
|---|---|---|
| **图文叙事**（短剧分镜版） | Flow 生图为主 + 代码运镜 | 有故事、有人物、有案例、要情绪 |
| **图解** | 代码画为主 | 有数据、要讲机制、概念推导 |
| **艺术** | 代码画（35 种风格） | 视觉/氛围为主，题材是艺术或情绪 |

**一段文案常常是混合的**（比如情感口播：三个案例是叙事、前后拆解是图解），
**所以路由要逐页定，不能只给整片定一个片型。**

### 二、模型多输出两个字段

```json
{ "filmType": "story",
  "skeleton": ["钩子", "案例一", "案例二", "案例三", "反直觉结论", "真相拆解", "行动建议", "落点"],
  "pages": [
    { "id": "04", "role": "案例一", "dur": 11,
      "title": "周先生的婚外关系因孩子网课弹窗暴露。",
      "narration": "……",
      "mode": "image",
      "imagePrompt": "中年男人坐在儿童书桌旁，手机屏在昏暗房间亮起，前景是作业本，右上留白，扁平插画风"
    } ] }
```

`mode` 的判断规则（写进提示词让模型自己选）：

| mode | 什么时候用 |
|---|---|
| `image` | 有人、有手、有具体场景、要质感和情绪 |
| `code` | 图表、文字、几何、抽象概念、需要连续变形或粒子 |
| `mixed` | 主体要好看，但局部要动（纸被压出形变、裂缝生长） |

### 三、一张静图怎么撑住 13 秒（短剧分镜版的核心手艺）

| 手法 | 做法 | 代码成本 |
|---|---|---|
| **慢推 / 横移** | Ken Burns，幅度 3-8% | 极小 |
| **分层视差** | 前中后景分开动；需要分层图（生成时要求"背景和人物分开"或抠图） | 小 |
| **明暗揭示** | 从暗到亮，或局部亮起（灯打开、手机屏亮） | 小 |
| **细节插入** | 同一场景的第二张图（特写），中段切进来 | 中（要生成 2 张） |
| **文字依次出现** | 屏上字在 0.3 / 0.6 / 0.85 三个时刻分别出来 | 极小 |

**五条叠起来，一页就有 4-5 个事件，不会闷。**

### 上游原生支持，不用改引擎

- `e.plate` —— 一张底图铺满
- `e.assets: [...]` + `IMG['...']` + `drawImage` —— 任意贴图，可多层（做视差）
- `key_green.py` —— 绿幕抠图（输出 RGBA 并记录原坐标）
- `CAM` / `CAM.track` —— 运镜
- 这些全部现成，只是我一直没接上
