# FRAMETELL 源码拆解（2026-10-16）

源码：`experiments/frametell-src/frametell-main`（公开仓库 zip，13 MB，AGPL-3.0）
上次只有录屏的拆解在 `experiments/competitor/README.md`（那次的结论是界面层面的）。
**这次读的是真源码**，结论和上次完全不同 —— 关键不在界面，在**画面是怎么造出来的**。

## 一句话

> **它不生成视频，它驱动一套组件库。模型当导演（挑组件、排时刻、配镜头），
> 引擎当动画师（每个组件自带动作）。**

它 README 自己就是这么写的：

> **效果稳，省 token。** 不是从零生成视频，而是驱动一整套成熟的视频引擎：
> **风格、组件、镜头运动、质量检查都是现成的。**

而它的示范片《测不准原理》**就是 DeepSeek 做的**（README 明写）。
所以"模型能力不行"不是根本原因 —— **我们把模型当动画师用了**。

## 一页画面长什么样（`styles/warm-story/example/pages/p03.js`，全部 21 行）

```js
ENGINE.visual('p03', (P) => {
  P.title('收益也会生钱', { accent: 'blue' });
  P.path('M-200 540 C ... Z', { at: 0, fill: 'greenF', dur: 0.3 });
  P.tree(360, Y0 + 18, 170, { at: 0.1, grow: 1 });              // 树：自带生长
  const x = (lt) => PV.lerp(460, 1500, k(lt));
  const r = (lt) => PV.lerp(28, 136, Math.pow(k(lt), 1.6));
  P.snowball(x, (lt) => surf(x(lt)) - r(lt) * 0.92, r,          // 雪球：自带滚动 + 自转
             { at: t1 - 0.3, spin: (lt) => (x(lt) - 460) * 0.55 });
  P.tag(860, 300, '每年 8%', { at: P.c(1) + 0.4, size: 48 });    // 标签
  P.cam([P.pan(P.c(3), 1040, 600), P.slam(t4 - 0.15, 1360, 620, 1.12), P.back(t4 + 0.9)]);
});
```

对比我们的贴图页：1300 字裸 canvas（`c.fillStyle` / `MD.cover` / 自己算时间）。
**它的每一行都是一个"有动作的对象"，我们的每一行都是"怎么画"的操作指令。**

## 六个机制（我们一个都没有）

| # | 机制 | 具体做法 | 我们的现状 |
|---|---|---|---|
| 1 | **语义组件库** | `engine/lib/` 28 个文件：`warm`（雪球/罐子/硬币/树/日历/手）、`gauges`（仪表/水箱）、`fsm`（状态机）、`pipeline`（管线）、`ranking`（榜单）、`scorecard`（记分卡）、`terminal`、`flowgraph`、`matrix`… 每个组件**自带出现/动作/收尾动画** | 我们只有**画图原语**（MO 缓动、CAM 运镜、TY 文字、DG 几何、RIG 骨架）。模型得自己想形状、算路径、编动画 |
| 2 | **时间跟着配音的词走** | `P.c(i)` = 第 i 句旁白的真实时刻；`P.cw(i, '雪球')` = 说到"雪球"这个词的时刻。分镜里写 `"at": "c1:三十六万"` | 我们**自己编三个时刻**（0.30/0.62/0.85），跟旁白毫无关系 —— 这就是"像翻页、不像讲清楚"的根子 |
| 3 | **镜头语法：hold → 快移 → hold** | 只用 `P.push / P.pan / P.slam / P.back` 四个预设。风格卡明写：**关键那一下短促推近 0.3 秒落定，然后停住** | 我们**整页均匀慢推** —— 正好是它点名禁止的做法（GRAMMAR.md：`no slow uniform push across the whole page`）|
| 4 | **风格卡（GRAMMAR.md）** | 一份 3KB 的硬规矩：一个隐喻物体贯穿全片、**主体占画面一半以上**、数字写在物体上不做数字卡、每 3-6 秒一个变化、禁霓虹渐变、禁"标题+三卡+箭头"的 PPT 脸 | 我们的提示词在讲"引擎契约"，风格约束是"一个隐喻物体"级别的软话 |
| 5 | **浏览器里量的检查器** | `tools/checks.mjs`：API 存在性、屏幕上有裸标记、文字出框、**文字进字幕带（y>905 直接判错）**、字号下限、重叠面积、运行时异常、调色板越界、**画面填充率** | 我们刚做了一半（静态查代码 + 抽帧像素），没有"填充率/重叠/字号"这些 |
| 6 | **编排器强制自检循环** | 每页：写 → lint → 关键帧截图拼图 → 模型看图改，**最多 3 轮**；改不动标"需要关注"**不阻塞**全片。每页独立会话、**并行** | 我们的导演回路是人工触发的；页面串行 |

## 它的流水线（`docs/ARCHITECTURE.zh-CN.md`）

```
新建（素材 + 时长 + 风格 + 音色 + 模型）
 → ① 分镜 Agent     → storyboard.json          ◆ 用户拍板
 → ② 口播 Agent     → script.js（PAGES + cues，每页 3-5 句）
 → ③ 配音           → 真实字级时间戳
 → ④ 画面 Agent × 页（并行，每页独立会话）
        编排器每轮强制：lint → 截图拼图 → 模型看图改（≤3 轮）
 → ⑤ 全片检查       → 只修跨页问题（颜色/物件一致性在这层）
 → ⑥ 渲染           → MP4 + SRT
```

**注意 ③ 在 ④ 前面**：先把话说死（时间戳定了），再让画面去贴话。
我们是反的：先写画面代码，配音到现在都还没接。

## 分镜的形状（`storyboard.json`）

```json
{ "id": "p03", "say": "收益第二年也开始生钱，像雪球越滚越大。", "core": true,
  "beats": [
    { "at": "c1", "object": "一颗小雪球", "action": "从坡顶开始往下滚", "camera": "横移", "text": "" },
    { "at": "c3", "object": "雪球", "action": "边滚边粘上雪，越滚越大", "camera": "跟拍", "text": "8%" },
    { "at": "c4", "object": "雪球", "action": "冲到坡底停住", "camera": "砸入", "text": "" } ] }
```

一拍五件事：**什么时候 / 什么东西 / 做什么动作 / 什么镜头 / 屏上什么字**。
"什么东西"就是**组件名**的候选，"做什么动作"就是**组件参数**。

## 它没有而我们有的

- **生成图**（Flow）：它的画面全是代码画的，所以风格必须收敛到 5 套预设里。
  我们的主体用生成图，**画面质感的上限比它高**（实测那只手它就画不出来）
- **可选画风多**：它 5 套，我们 6 套命名预设 + 上游 35 风格
- 我们的内容域是**情感/心理/叙事**，不是知识科普 —— "隐喻物体贯穿全片"这套对我们同样适用，但物件的调子不同

## 我们该借什么（按杠杆排序）

1. **时间轴改成跟配音的词走**（最大杠杆，成本最低）
   配音 → `tools/transcribe.py` 拿字级时间戳 → 每一拍写 `at: "c2:雪球"`。
   这一步不用改架构，就能让"画面在说到的那一刻出现"，立刻从"翻页"变成"在讲"。
2. **镜头语法改成 hold → 快移 → hold**（成本极低，改提示词就能做）
   禁掉"整页均匀慢推"。改用：停住 → 0.3 秒推到主体 → 停住。
3. **造我们自己的组件库**（中等成本，收益最大）
   用现有原语造 20-30 个**我们内容域的语义组件**：
   `hand` 手（开/合/指/按/递）、`paper` 纸（折/撕/皱/压痕）、`crack` 裂缝（生长/分叉）、
   `door` 门（开合/缝里透光）、`phone` 手机（亮屏/通知条）、`figure` 背影（站/坐/走/跪/消散）、
   `daycycle` 时间（钟/日历/日夜）、`compare` 双柱、`balance` 天平、`steps` 步骤、
   `venn`、`timeline`、`scene`（桌面/床沿/门口/地铁）…
   笔触参数从画风锁来（线宽/抖动/端点），保证和图是同一支笔。
4. **页面改成"填规格"而不是"写代码"**（彻底消灭一类失败）
   模型输出 JSON（组件 + 位置 + 时刻 + 参数 + 镜头），我们的渲染器把它变成 draw。
   语法错、未定义名、API 用错、画歪 —— 整类问题消失，代码量从 1300 字掉到 200 字。
5. **检查器补齐**（借它的清单）
   填充率、字号下限、重叠面积、字幕带、调色板越界、运行时异常 + 关键帧截图拼图给模型看。
6. **页面并行**（它的 ④ 是并行的；我们现在串行，26 页 20 分钟）

## 直接抄的清单（文件级）

| 它的文件 | 抄什么 |
|---|---|
| `packages/agent/prompts/PAGE.md` | 页面 agent 的提示词结构：Flow / How to write / How it moves / Hard rules |
| `packages/agent/prompts/LIB.md` | 组件目录的写法：一行一个文件 + 每个组件一句话 + **已知坑清单** |
| `styles/warm-story/GRAMMAR.md` | 风格卡的写法：一句话 / 画面 / 运动与镜头 / 节奏 / 禁则 |
| `packages/engine/tools/checks.mjs` | 检查项清单（尤其：填充率、字幕带、重叠、字号） |
| `packages/engine/lib/*.js` | 组件的**接口形状**（`(x, y, 数据, {at, dur, ...}) → 句柄`），不要抄实现（它是 HTML/CSS 3D，我们是 canvas） |
| `packages/engine/tools/use-extra.mjs` | 组件按需拷进项目 + 登记（省 token 的做法） |

## 一句话结论

**我们的模型不是不够聪明，是我们让它干了它最不擅长的活（发明形状 + 算几何 + 编动画），
同时没给它最擅长的活（判断"这一页该用什么方式讲"）。**
它的架构把"画"从模型手里拿走了 —— 模型只做决策，引擎保证下限。
