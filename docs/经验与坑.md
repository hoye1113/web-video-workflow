# 经验与坑 · video-factory

按时间倒序。每条都写上「现象 → 根因 → 怎么修 → 以后怎么防」。
只记**实测撞到过**的，不记猜测。

---

## 一、平台与环境的坑

### 1. 命令行不读系统代理，浏览器读

**现象**：Chrome 能打开 Flow 和 Gemini，但 `curl` / Python 下载东西一律超时；
HuggingFace 下不了模型；Flow 的图床 `flow-content.google` 返回 `http_code=000`。

**根因**：这台机器在 `HKCU\...\Internet Settings` 里设了系统代理 `127.0.0.1:17890`。
Chrome 读它，命令行工具默认**不读**（只看 `HTTP_PROXY`/`HTTPS_PROXY` 环境变量）。

**怎么修**：脚本里显式设环境变量，或者从注册表读出来（`tools/transcribe.py` 里的
`use_system_proxy()` 就是干这个）。

**以后**：任何要联网的脚本，先问一句「浏览器能通吗」。能通就是代理问题。

### 2. Windows 下中文 JSON 的编码

**现象**：`render.py` 读 spec 直接崩，`UnicodeDecodeError: 'gbk' codec can't decode`。

**根因**：Python 的 `Path.read_text()` 不带 encoding 时用系统区域编码（中文 Windows 是 GBK），
而仓库里的 JSON 是 UTF-8。

**怎么修**：所有子进程注入 `PYTHONUTF8=1`。上游代码一行不改。

**反噬（重要）**：`PYTHONUTF8=1` 之后，**`subprocess.run(text=True)` 默认用 UTF-8 解码**，
而 Windows 的 `cmd` / PowerShell 吐的是 GBK。于是 `cmd /c mklink` 的输出解码崩掉，
**把整个请求线程打挂**，请求永远不返回（不是慢，是死了）。

**以后**：**每一个** `subprocess.run(..., text=True)` 都要写 `encoding="utf-8", errors="replace"`。
本项目 15 处全加了。

### 3. PowerShell 的 `ConvertTo-Json` 会把长字符串包成对象

**现象**：服务收到 `{"script": {"value": "...", "PSPath": "..."}}`，而不是一个字符串。

**根因**：`Get-Content -Raw` 返回的字符串带着扩展属性（PSPath、ReadCount 等），
PS 5.1 的 `ConvertTo-Json` 把属性一起序列化。

**怎么修**：发送前 `[string]$s` 强转成纯字符串。

**教训不只是"改测试脚本"**：它暴露了应用缺**信任边界上的类型校验**。现在有 `text.text_field()`：
能认 `{value: ...}` 这种形状，真不是文本就明确报错，不让它一路崩到后面去。

### 4. 目录联接（junction）可以零拷贝把项目挂进引擎

**背景**：上游引擎只认自己根目录下的 `demos/<名>/`，而我们的项目要放在 `projects/`。
复制整个引擎太重（几十 MB × 每个项目）。

**做法**：`cmd /c mklink /J` 建目录联接（**不需要管理员**，符号链接才需要）。

**坑**：`Path.resolve()` 会把联接解析成真实路径，于是「路径越界检查」判定
`engine/demos/<项目>` 跑出了 `engine/` → 403。改成用 `os.path.abspath` 做**字面**归一化，
不跟随链接。

## 二、架构上的坑

### 5. 长调用不能同步等

**现象**：点「切成页面」之后请求挂满 25 分钟不返回，会话被拖死。

**根因**：三层叠加 ——
① LLM 调用是同步的，前端死等；
② 没有总超时；
③ 私有 opencode server 会跟着桌面版服务重启一起死，而代码**只在第一次调用时探活**。

**怎么修**：
- 所有长调用改成**后台任务**（和渲染同一套队列），提交立刻返回 job id，前端轮询。
  实测提交耗时从 25 分钟变成 **0.1 秒**。
- `LLM.TIMEOUT = 240`，超了明确报错。
- `generate()` **每次调用前**探活，不健康就重建私有 server。

### 6. 引擎的"拒绝渲染"是好事，但要会读

上游引擎在场景代码出错时**拒绝启动**（不静默出空白帧），这是对的。
但它把错误写在 `[page] BOOT FAILED` 里，需要从子进程 stdout 捞出来看。

实际撞到的：`02: 文件里没有 SCENES['02'] = { draw(c, lt, t) }`。

## 三、提示词的坑（最值钱的一类）

### 7. 契约里的占位符要真的替换掉

**现象**：模型写的场景文件注册成 `SCENES['p02_window_paper']`，引擎按 id `02` 找不到，拒绝渲染。

**根因**：引擎契约那段是共享常量，里面写的是字面量 `SCENES['<镜号>']`，
而页号是通过另一个参数传的，**模型从没被告知"注册名必须精确是 02"**。

**怎么修**：两处 ——
- 契约里改成 `__SHOT__` 占位，发提示词前 `.replace("__SHOT__", sid)`；并且明写
  「注册名必须精确是 `SCENES['02']`」
- **写盘前做确定性校验**：只有一个注册名但不是目标名，就地改回；其余情况直接报错。

**教训**：提示词里的**契约性字面量**（注册名、文件名、路径）是硬约束，
不能留占位符让模型自己猜。而且**每一处都要配一条确定性校验兜底**。

### 8. 模型把引号写进字符串，JSON 被撑破

**现象**：评审明明返回了完整结构，解析却报「模型没有返回合法 JSON」，
于是一整轮回路白跑（渲染、看图都花了钱）。

**根因**：模型在字符串值里用了裸引号：

```
"…违反"不发光、单笔触"的画风锁"
```

**怎么修**（三层兜底，`app/text.py`）：
1. `extract_json` 正常解析
2. 失败 → `repair_json` 扫一遍，把「不在 key/值边界上的引号」转义掉
   （边界判断：引号后面第一个非空白字符是 `: , } ]` 之一 → 它是收尾引号；否则是裸引号）
3. 还失败 → `loose_fields` 用正则把 `score` / `ok` / `problems` / `fixes` 抠出来

同时在评审提示词里明写「字符串里不要用引号」。

**教训**：**凡是让模型输出结构化数据，都要准备容错解析**。模型偶尔会在字符串里放
引号、换行、代码块围栏，纯 `json.loads` 不够。

### 9. 重跑切页必须挪走旧场景

**现象**：重跑「切成页面」换了页列表（标题都变了），但 `scenes/` 里的旧代码还在，
`sync_eras` 照样把它们排进时间轴 —— **观众看到的是上一代页面的画面**。

**怎么修**：
- 重跑切页时把 `scenes/*.js` 挪到 `scenes_old/<时间戳>/`（挪不是删，要找回还有）
- 给每一页加**指纹**：写场景时把当时设定（标题/画面/旁白/时长/镜头/屏上字）的
  sha1 前 10 位记进 `shot['sceneHash']`；页的设定改了，接口就返回 `stale: true`，
  界面把那一页标黄，提醒要重写

**教训**：**任何"按 A 生成 B"的关系，都要能判断 B 是不是还配得上 A。**

### 10. 窄窗口下三栏会挤成一团

**现象**：`300px | 1fr | 340px` 的固定宽度，在 763px 宽的窗口里把中间栏压成 100px，
画风预设一行只放得下两个。

**怎么修**：加一条媒体查询，`max-width: 980px` 时改成上下堆叠。

**教训**：三栏布局的固定宽度之和，不能超过常见窗口宽度的一半。

### 8. 让模型"自由发挥"分镜，等于没有分镜

**现象**：让模型自由切分，切出 35 个镜头、**全都是 6 秒**，节奏完全平；
标题是画面描述（"一部手机"）而不是论点。

**怎么修**：先定**叙事骨架**再切页。情感内容用
`提问 → 案例 → 共性 → 拆解 → 建议`（模型自己演化成
`钩子 → 案例一/二/三 → 反直觉结论 → 真相拆解 → 行动建议 → 落点`）。

**效果对比**（同一份 2310 字文案）：

| | 自由发挥 | 叙事骨架 |
|---|---|---|
| 页数 | 35 | 28 |
| 每页时长 | 全是 6 秒 | 10-17 秒，平均 13.4 |
| 标题 | 画面描述 | **论点** |
| 旁白对齐 | 无 | **100%**（16 段一字不丢） |
| 贯穿意象 | 手机（普通） | **一张纸 + 一道裂缝**（来自原文"窗户纸"） |

### 9. 页要够长（学 FRAMETELL）

**现象**：一镜 2-8 秒是"快切片"的逻辑。解说/口播片不一样：**一个知识点 = 一页 = 10-15 秒**，
页内靠元素依次出现撑节奏。

**做法**：提示词里要求"一页至少 4 个先后发生的事件，用 `lt` 依次揭开"。

### 10. 风格预设不是模板库，是「画风描述 + 色板」

**现象**：一开始把 35 种艺术风格 + 8 种语法全摆出来给用户选——43 个选项，普通人没法用。

**做法（学 FRAMETELL）**：收成 6 个命名预设，每个 = 名字 + 一句人话 + 画风一句话 + 一套色板。
色板**直接用上游 `references/色板.md` 的 8 套现成色板**，不另造色（免得踩蓝紫禁区）。

选中后写进项目的是 `look / palette / character` 三个字段，**场景代码由模型按这三个字段现写**。

## 四、流程上的坑

### 11. 改哪一页，一定要清哪一页的旧帧

**现象**：评审说「第 3、5 帧主体变成窗框」——但这一镜只该有 3 帧。
上一版（时长 14 秒）留下的两帧还在目录里，评审在**混两代画面**。

**根因**：`/api/stills` 不清目录（导演回路里清了，API 那条漏了）。

**怎么修**：渲帧前先删 `t*.png`。另外加了一条守卫：**帧比代码旧就拒绝评审**
（说明上一次渲染失败了），否则会给出假分数 —— 实测分数从 4 掉到 3，
其实评的是上一版画面。

**教训**：任何"读中间产物"的环节，都要检查**新鲜度**。

### 12. 改坏了是常态，必须比稿

**实测记录（同一个模型、同一套提示词）**：

| 场景 | 结果 |
|---|---|
| 沙漏，第 1 次改 | **改坏**（沙漏放大到出画、底盖挪进玻璃中间） |
| 沙漏，第 2 次改 | 改好（7 分 → 8 分） |
| 第 02 页，第 1 次改 | **改坏**（分数 4 → 3） |

**结论**：不能信任单次修改。导演回路必须**每轮存档 + 打分 + 最后只保留得分最高的那版**。

### 13. 评审是可靠的，"改"是不可靠的

**现象**：评审**每一轮**都能挑出 5-6 条具体问题，带位置、带颜色值、带改法，
而且都是真的。但模型改不动它们 —— 下轮还是同样的几类。

**反复出现的五类**（每一页都中）：

1. 色相越界 / 渐变 / 柔光（"那块土黄不在色板里"）
2. 形状越界（"裂缝压在下边框线上、伸进阴影里"）
3. 线宽不统一（"框线比裂缝粗好几倍，等于两套笔触"）
4. 构图空（"主体挤在右侧 x=3/4，左半边整片空白"）
5. 该"停"的镜头在动（"第 1→2 帧纸的倾角变了"）

**这是最有价值的一条**：这五类里有一半**根本不用看图**，脚本就能查。

## 五、从 anatomy 学到的（另一个技能，做等距技术图的）

来源：https://github.com/wheresryan22/anatomy

### 14. Measure, then look（先量，再看）

它有两道**确定性检查**，跑不过不许交付：

```sh
node build.mjs --audit          # 必须打印 audit passed，每项失败计数为 0
node scripts/lines.mjs page.html # 必须打印 line ends: 0
```

它的原话：

> **靠眼睛修一个特写**：手调遮挡键或挪一个路点直到某张截图看着对，会破坏另一帧。
> Raptor 的手调键在 1× 下看着没问题，**有 323 处遮挡顺序错误**。
> **Measure, then look.**

**对我们的意义**：画质验证不能只有"模型看图"，必须有"脚本量数"。

### 15. 对象即解释（对情感内容极其对症）

> **不要画框框、箭头、标签。发明一个真实的物，它的运作本身就是那个概念。**

它的两种失败模式："太抽象"（浮动板块代表"层"）、"太空洞"（大平面加几条线）。

**实测我们做到了**：原文一句"不把这个**窗户纸**捅破"，被切成 10 页共用一个物
（一张纸 + 一道裂缝）：按住 → 裂开 → 划线 → 压平 → 撕成两半 → 抓住两端 →
推进麻药 → 重新对齐。

### 16. 构图有个数字标尺

它写「主体居中，占卡片 **55–65%**」。
我们的评审说「沙漏只占 36%」—— 正好对上。**这个数字可以直接进评审提示词。**

## 六、确定性与非确定性检查的边界（最终结论）

写了两层检查，各自验过：

| | 能抓 | 抓不到 |
|---|---|---|
| `scene_lint`（读代码，秒级） | 渐变、`Math.random`、显式线宽档数、有没有填底、色值字面量 | **计算出来的**线宽；混合色 |
| `frame_audit`（量帧，秒级） | 新色相、构图框太小、重心偏移、帧差（该停没停 / 画面死了） | 「主体太细读不出」「像随手画的」这类语义判断 |

**实测反例**：评审一眼看出「主体太小、像随手画的 3」，
而 `frame_audit` 报「内容框 63%×84%、重心居中，通过」。

**所以：两条腿互相替代不了。**
- 确定性检查抓**规则性违反** —— 快、免费、100% 召回，但不懂语义
- 模型看图抓**语义和可读性** —— 慢、要钱，但能抓本质

**正确用法是协同，顺序按成本排**：

```
写代码
  → scene_lint（秒级）    红灯就改，不渲、不评
  → 渲帧（10s）
  → frame_audit（秒级）   红灯就改，不评
  → 模型看图（40s，花钱）
  → 按意见改 → 比稿留最高分
```

### 色板纪律的正确规则

**不是**「渲出来的颜色必须精确在色板里」—— 那会把抗锯齿边缘和允许的明暗层次全报成错。

上游 `references/色板.md` 的原话是：「**加减明暗、透明度可以，别引入新色相**」。

所以 `frame_audit` 查的是**色相**（饱和度 ≥0.25 且亮度 ≥40 的像素，
色相离所有色板色相都超过 35° 才算越界）。

两个额外要处理的：
- 近黑像素的色相没有意义（抗锯齿会把它算成新色相），要加亮度下限
- 阈值要按"一块看得见的区域"定，不是按总面积。实测一个占全画面 0.2% 的土黄块，
  人一眼就看见，而总面积阈值会放过它。改成**分格**（3×3），任一格超过 0.1% 就报

## 九、2026-10-15 当天进展快照

**已跑通（端到端）**
- 文案 → 叙事骨架 → 页列表（28 页 / 356 秒 / 旁白 100% 对齐）
- 页 → 场景代码 → 渲染 → 两层检查 → 模型评审 → 比稿 → 回滚最优版
- 界面上：六套画风预设、骨架条（带每段页数）、页列表（带代码状态点）、
  连续预览、任务队列、下一步签字按钮
- 用 bsk 在真浏览器里点过一遍，元素齐、状态对

**关键数字**
- 切页：79.5 秒（26 页）／138.5 秒（28 页，带画风锁）
- 写一页场景代码：130 秒（长输出要放宽到 420 秒超时，240 会误杀）
- 评审一次：24-40 秒
- 改一次代码：100-200 秒（**失败率高，有硬超时兜底**）
- 导演回路 3 轮（含一次超时）：500 秒
- 渲 3 帧：10 秒
- 一条 5.9 分钟的片子若每页都跑 2 轮回路 → **约 4 小时**（需要并行才实用）

**提示词迭代记录（第 02 页，一轮一版）**

| 版本 | 得分 | 提示词改了什么 | 结果 |

| v2 | 5/10 | 加「主体连载体占 55-65%」「单一笔触、不许加刺」 | **纸大了，但裂缝反而相对更小**（70%→35%），且形状换身份 |
| v3 | 6/10 | 把「主角」和「载体」分开：主角自己占画面 45%+；形状全页保持同一身份；明写不许渐变/描粗边/柔光 | **对了**：裂缝是一条干净的带分叉细线，从底长到顶；静态检查 + 像素检查全过 |

**v3 之后评审提的问题变细了**（纸太小 → 分叉末端断在纸面中央、缺铅笔顿挫、字幕抢重心），
说明回路在往细处收敛。

**又一处自相矛盾（已修）**：评审要「线宽 1.5-2.5 像素随机扰动、不透明度抖动」（手绘铅笔感），
而我写的是「全画面只用一档线宽」，把它逼成了等宽矢量描边，反而更假。
**「同一支笔」不等于「等宽」** —— 一支铅笔本来就有粗细顿挫。
提示词已改成：全画面像同一支笔画出来的（允许自然扰动），要避免的是那**两套笔触**。

**一条元教训**：我扫一眼并排图觉得「新版明显更好」，评审逐帧量出「裂缝长度从 70% 掉到 35%、
第 2 帧是黑三角第 3 帧变细线、颜色跨帧不一致」。
**人对画面的快速判断不如逐帧评审可靠** —— 别用自己的直觉去否定评审的结论，
要么量数，要么把两版并排到同一张图上逐帧看。

**另一条**：三次评审给的分数是 6 → 5 → 6，但**画面质量是单调变好的**。
说明分数有 ±1 的噪声，**不能用单次分数判断进展**，要看它提的问题是不是在往细处走。

## 十、连续多页的坑（2026-10-15 下午，第一次跑通 3 页连播）

**跑通了**：页 01/02/03 各写代码 → 各过两层检查 → 各渲 mp4（13/11/13 秒）
→ `ffmpeg concat` 拼成 **37 秒 / 1110 帧 / 2.4 MB** 的片子。

**但发现一个真问题：同一个意象，每页长得不一样**

| | 页 01 | 页 02 | 页 03 |
|---|---|---|---|
| 裂缝 | 横向，从中间裂开 | 纵向，从底往上 | 只有一条淡压痕 |

页 01 结尾纸已经裂开了，页 02 开头又变回一张完好的纸 —— **观众会觉得倒回去了**。

**根因**：每一页的场景代码都是模型**独立**写的。提示词里只给了前一页的
**标题和位置**，没给它**画面上长什么样**。所以同一个「纸 + 裂缝」，
每页被重新发明了一次。

**这不是画风不一致，是「同一个物件的具体形状」不一致** ——
比画风不一致更隐蔽，因为单看每一页都没毛病。

**上游有现成的解法**：`window.SCENE_LIBS`。
一个项目可以有一个共享脚本，里面定义"这个世界"的东西
（那张纸、那道裂缝、那只手），每页的场景都调它。
`demos/long_scroll/lib/world.js` 就是这么组织的（长卷穿越片）。

**待做**：给每个项目生成一个 `lib/world.js`（定义贯穿意象的几何），
场景提示词要求"用 world 里的东西，不要自己重画"。

### 另一条：模型会自作主张画手

页 01 的 note 是「一只手，按住一张还没裂开的纸」，模型就真的用代码画了一只手 ——
**一坨深灰色的东西，四个短指头，读不出是手**。

PRD 里早就写了"代码画不好手，该交给生成图"，但提示词没明说，模型就自己上了。

**待做**：场景提示词里明写「note 里出现手、人、脸时，不要把代码画手当作第一选择 ——
要么改成不出现手的表达（只画纸和被压出来的形变），要么留给生成图补」。

### 一条流程上的悬案

写页 01 和页 03 的任务都报「超时失败」（420 秒），
**但两个场景文件都写出来了**，而且内容是对的（注册名正确、色板一致、能渲）。
时间戳显示文件是在任务报失败之后 35 秒写的。

怀疑是：`opencode api post` 那一层超时被杀，但**服务端的生成还在继续**，
某个路径把结果落盘了。没查清。**暂时按"超时后要去确认文件在不在"处理。**

**还没解决**
- 整片 28 页的完整出片（渲染全部页 → 拼接）从来没跑过
- 低饱和度的冷色（评审抓到「投影偏冷蓝」）不在像素检查的射程内
- 「主角太细读不出」这类语义问题只能靠模型看图；**「主角尺寸」这条也许能量**，
  但需要知道"主角"是画面里的哪一块，还没想出办法

## 十七、生图自动化（bsk 驱动 Flow）踩的坑

这一段是 2026-10-15 把「读 imagePrompt → 去 Flow 生图 → 下载落盘」做成自动任务时，
连着踩出来的。每条都是"看起来对、其实没生效"，写下来省得重踩。

### 1. 点生成按钮**必须用 bsk 的真实点击**

现象：`evaluate` 里 `button.click()` 返回成功、按钮也不 `disabled`，
**但页面毫无反应**，干等 240 秒什么都没有。

根因：React 那边的处理没被触发。JS 的 `.click()` 在这个按钮上不顶用。

修法：先 `bsk observe` 拿到按钮的 ref，再 `bsk click @eNN`。
（生成按钮是个**图标按钮**，可见文字是 `arrow_forward`，
真名在 `aria-label="Start generation"` 上 —— 按文字找永远找不到。）

### 2. 认"新出的图"要按**域名**，不能按尺寸

现象：收回来一摞**彩色毛毡垫的产品图**，跟提示词毫无关系。

根因：我为了"更宽容"把过滤从 `src 含 flow-content.google` 放宽成
`naturalWidth >= 800`，于是把**界面上的广告图**一起收走了。

修法：只认 `src.includes('flow-content.google')`。
尺寸判据放到**浏览器里 fetch 回来之后**再判（`createImageBitmap` 拿真实宽高，
小于 900 的直接丢），那边才是可信的。

### 3. 图多了以后，"等不到新图"是被**懒加载**坑了

现象：批量跑到第 9 页开始，**每一页都报"240 秒内没等到新图"**，
但手动开个新会话试一次，45 秒就正常出图。

根因：项目网格里的图越积越多，新图落在**视野外**；
浏览器对 `loading="lazy"` 的图不触发加载，`naturalWidth` 一直是 0。
我的检测要求"`naturalWidth > 400` 才算数"，于是永远等不到。

修法：检测只看 `img.src`（懒加载的 img 也有 src），
**不要求已经加载完**。真正的加载交给后面的 in-page `fetch`。
（教训：**"等一个已经存在的东西"和"等一个会被渲染出来的东西"是两回事**，
判据不能依赖渲染状态。）

### 4. 首页会弹 **Agree / No thanks** 的条款弹窗

第一次跑会挡路，而且它出现的位置没有规律。
修法：进项目之前统一扫一遍 `get started / 知道了 / Agree` 三个按钮点掉。
（点 Agree 是替用户做的决定，日志里要说一声。）

### 5. 450 秒才超时的任务，要留现场

只报"240 秒没等到新图"，人只能对着这句话猜。
现在超时会把**页面文字 + 图列表 + 按钮列表**打进任务日志 ——
下一次出问题，日志自己会说。**这是排查成本最低的一步，应该一开始就做。**

## 十八、长任务不许攥着项目副本（丢更新）

**现象**：`07_1.png / 08_1.png / 10_1.png` 三个文件**都在硬盘上**，
但 `project.json` 里这三页的 `images` 字段是空的 —— 项目"不记得"图生过了。

**根因**：写场景代码要调模型（一分钟）。它开头 `store.load()` 拿了一份项目副本，
模型调用期间**生图任务往 project.json 里写了三页的 images**，
写场景的活儿最后一记 `save()` 把整份旧副本盖回去 —— 那三个字段就没了。

**修法**：加了 `store.patch_shot(name, sid, **fields)`（**现读现写**，只改几个字段），
所有落盘改走它。**规矩：任务里不许跨模型调用持有项目副本。**

**以后怎么防**：任何"读 → 想很久 → 写"的流程都要问一句
"这段时间别人会不会也写这个文件"。会，就必须现读现改，或者上锁。
（这类 bug 特别阴：单独跑永远不出，两个任务并行才出。）

## 十九、存盘前跑一遍语法检查（50 毫秒换十几秒）

**现象**：模型写的场景文件结尾是 `}})();` —— **多一个大括号**。
不检查的话，这个错要等到**渲染抽帧**才暴露：起 Playwright、等十几秒，
报回来还是句 "Unexpected token '}'"，得人肉回去数括号。

**修法**：`app/scene_check.py`，存盘前用 `node --check` 解析一遍（node 在 `C:\Program Files\nodejs`）。
有错就带着**错误信息 + 原代码**让模型**只修那一处**（明写"别的一概不许动"），
修完再检查，还错就让任务失败。服务端写场景、导演回路改代码，两处都接上了。

**为什么值得**：这是**最便宜的确定性检查**——50 毫秒，拦掉一整轮渲染 + 评审（十几秒 + 一次模型调用）。
两条腿验证（确定性检查打头、模型看图收尾）的第一条腿就该是它。

## 二十、量出来再交给模型（"量图"）

**问题**：评审从第一页挑到第十八页，翻来覆去就那两句 ——
「主体太小」「重心偏在一侧」。这是当前画面质量的天花板。

**关键转念**：这两条**是能量出来的**。`app/checks.py` 的像素检查本来就在算
内容重心和内容框，只是过去用来"扣分"，没用来"给条件"。

于是加了 `app/measure.py`：把主图丢给模型问四个数
（主体是什么、外接框 0-1 相对坐标），**量一次存进项目**，
写场景代码时当成已知条件交出去：

    - 主体是：一只正在折叠纸的手
    - 外接框：宽 28%、高 56%，中心在 (0.86, 0.72)
    - 铺图参数：z 从 1.00 走到 1.07，fx = 1.00，fy = 0.50
      这三个数直接用，不要自己另算一套。

实测模型**照用了**（18 页里 fx/fy 和量出来的值逐个对得上）。
好处是两层的：模型不用猜构图（少一类错），而且**同一份数据被反复用**
（写代码用、体检用、以后重画也用），不会每处各飘一套。

**为什么先量再给，而不是让模型自己看图定**：
让模型"看一眼决定怎么裁"每次都会给不同的答案，同一页重跑两遍构图就不一样了。
量出来的是**死的四个数**，存下来，谁来用都一样。

### 顺着量图发现的一条硬道理：构图歪是**裁不回来**的

我一开始想当然：主体偏右，那把画面往左推一点不就居中了？算了一遍才明白：

`MD.cover` 的 `fx` 是"以图上哪一点为焦点"，**不是"把主体摆到中间"** ——
它的作用是让某个点落在画面的同一个相对位置，等于**保持现状**。

要把主体从 c 挪到正中，图上得有多余的料可裁，推导下来需要 `z >= 0.5 / (1 - c)`。
主体在 c=0.86 时这要求**放大 3.57 倍** —— 1376 宽的图放到 3.57 倍就是糊的。
（第一版我还把公式写错了，算出 1.56，测试用例一跑就露馅。
**这种事必须拿几个已知答案的用例验一遍**，不能靠"看着对"。）

**所以**：
- 能给代码的只有"推近一点"（主体太小就推近，最多 1.35 倍，再多就糊）；
- **构图问题必须在生图那一步摆正** —— 于是有了"生图体检"：
  逐页量，只对不合格的页带着修正要求重画（"主体放正中央、占一半、不要孩子"），
  重画后再量一遍确认。
- 量回来发现"裁不回来"时，**代码里如实写一句**
  （`——裁不回来，这一页的构图问题只能记在生图上`），
  而不是假装推一下就当解决了。

### 顺带：确定性检查和模型评审会**互相印证**

页 01 那条，像素检查独立量出"内容重心 (0.65, 0.57)、内容框只占 37%×86%"，
模型评审说"主体压在右侧并出血" —— 一个量数值、一个说人话，说的是同一件事。
两条腿都指出来的问题，基本可以确定是真问题（不用怀疑是模型的噪声）。

反过来也验证了一次：评审说"三帧取景完全相同，缓推没体现"，
但像素检查量出帧间差异 **2.96**（阈值 1.0），
我并排看三帧也确实在推 —— **这一条是模型看走眼了**。
（阈值 1.0 到实测 2.96，余量不算大。6% 的推近本来就容易看漏。）

## 廿一、成片验收清单（"画面好看"不等于"能发"）

**起因**：整片渲完才发现 —— **既没有字幕，也没有声音**。

两条链路里根本没有这两步：`do_film` 拼完就完事，`-an`（不要音轨）；
而画面里的**屏上字**又画在画面底部，就算后加字幕也会叠在一起。

**根子上的错**：过去只在验收"画面对不对"，从来没验收过"**这条片子能不能发出去**"。
画面再好看，没字幕没声音、字还和字幕打架，就是一条不能发的片子。

**以后每次出片，照这张单子过一遍**（能自动化的都要自动化）：

| 项 | 谁来保证 |
|---|---|
| 画面：每页渲出来了、没有黑帧 / 死帧 | 帧像素检查（已有） |
| **字幕**：有字幕、时间轴对得上、烧进画面 | `app/subtitle.py`（按页 dur 累加当时间轴） |
| **字幕带**：屏上字 / 主体不许进下方 18% | 静态检查 `scene_lint` + 生图提示词 |
| **声音**：旁白混进去了（`out/旁白.m4a`） | `do_film` 里有音轨就混，没有会在日志里说明 |
| 时长 / 画幅：在目标区间（3-5 分钟、1920×1080） | 出片时打印，超了要报 |
| 页数完整：没有"跳过"的页 | `do_film` 会把缺的页列出来，不假装完整 |

**教训**：**验收标准要写在"流程"里，不能靠人临场想。**
这次是靠使用者一句"作为视频为什么没有字幕"才发现的。

## 廿二、字幕带：例子即模板，错一次会被复制二十遍

### 上游早就留了位置 —— 先翻上游，别自己造

`clip.js` 里有：

```js
const safe = { top: 0, bottom: 0, left: 0, right: 0, ...(spec.safe || {}) };
// 让开的边（px）：管线烧录字幕、平台角标要用的地方
console.warn(`... spec.safe 被忽略：字幕带可能压在字上`);
```

上游把"字幕带要留出来"这件事当成**管线契约**写在代码里，还留了一行警告。
我们从来没接上，因为**开工时没有把上游的 `safe` 概念翻一遍**。

**教训**：接手一个渲染引擎前，先把它的"契约类概念"列一遍
（safe / plate / counter / transition / PUNCH ...），
这些是上游踩过坑之后留下的位置，自己重想一遍通常是白想。

### 例子即模板

场景提示词里有一段"参考例子"。它的文字 y 写的是：

```js
LINES.forEach((s, i) => word(s, [...][i] || 0.85, 880 + i * 74));
```

**880 正好在字幕带里**（字幕带从 y=885 起）。模型把它当模板抄了 ——
26 页里 **20 页**的屏上字全在字幕带里。

**教训**：提示词里的参考例子**不是说明，是模板**。
例子里出现的每个数字都会被复制；**例子必须是"完全正确"的那一版**，
不能"先随便写个能跑的，回头再调"。写例子要跟写契约一样小心。

### 两道新检查（都是秒级、免费的）

1. **屏上字不许进字幕带**：扫"画字"那几行里的数字（模型写字位置都是字面量，
   实测 26 页全是 `fillText(s, 150, 880 + i * 74)` 这个形状），
   超过 `subtitle.safe_bottom()`（1080 上是 855）就报。
2. **做法检查**：贴图页的代码里必须真的**铺了图**（有 `MD.cover(` / `IMG[`）。
   这条抓到一个真事：页 02 被模型"重画"成了手画纸裂缝，图完全没用上（见下节）。

### 存盘前先过静态检查（最便宜的一条腿）

以前是"写完了 → 渲帧 → 评审"，静态检查只在导演回路里跑。
现在**存盘之前就先跑一遍静态检查**，没过就让模型改一轮，过了才写文件。

理由很简单：静态检查是**秒级、免费**的；渲帧 + 评审要十几秒加一次模型调用。
**根本不该把没过静态检查的代码存进去**。过了才存，后面每条链路都省一遍。

（对应地加了 `/api/lint_fix`：只按检查意见小改，不重跑整页生成。
实测整页重写 1.5-6 分钟，只改检查项 30-40 秒。）

## 廿三、`opencode run` 是个**有文件工具的 agent**（悬案破了）

**悬案**（经验与坑第 10 节记过）：写场景的任务报"超时 420 秒失败"，
**但场景文件在 35 秒后又出现了**，内容还是对的。当时没查清，"暂时按超时后去确认文件在不在处理"。

**现在搞清了**：`opencode run --standalone --model ... <提示词>` 起的是一个
**能自己调用工具的 agent**，不是纯补全。它读得懂"把这个场景文件写出来"，
于是**自己动手把文件写进了工作区** —— 我们的 Python 代码只是等它返回文本，
所以进程被超时杀掉时，文件其实已经落盘了。

**两个后果，都要防**：

1. **超时 ≠ 失败**。现在 5 页"超时失败"的代码页，文件全都是好的。
   所以超时之后**必须先看文件在不在、对不对**，再决定重跑。
2. **它可能"顺手"改别的东西**。页 02 就是这样被害的：它是贴图页
   （`mode=image`，该 `MD.cover` 铺图），却被写成了 6660 字的手画场景。
   现在有了"做法检查"能当场拦住。

**给提示词时的规矩**：明确说"只输出代码，不要动工作区里的文件"。
但要**假设它可能会动**，所以落盘之后要验（模式检查 + 语法检查 + 静态检查）。

## 廿四、找个静态检查器扫一遍，别靠"跑一遍才知道少了哪个 import"

**现象**：整片渲染失败两次，两次都因为同一个低级原因 —— **漏了 import**：

- 第一次：`name 'UV' is not defined`（我用的是 `jobs.py` 里的 `UV`，server.py 没引）
- 第二次：`name 'subprocess' is not defined`（`_run_sync` 里用了，顶上没 import）

代价：一次是 26 页并行渲染刚要开始就全灭；一次是白等 30 分钟的失败任务。

**修法**：`uv run --with pyflakes python -m pyflakes app/*.py` —— **两秒钟扫出全部未定义名**。
（顺手还扫出几个没用到的 import 和一个 f-string 忘了占位符。）

**规矩**：改完代码**先扫一遍再提交任务**，尤其是那种"要跑半小时才知道错了"的任务。
**用工具的检查，永远比用运行时的检查便宜。**

这条和前面几条是同一个道理的三次重演：

    能静态查的（语法、未定义名、屏上字越界、做法用没用图）→ 存盘前就查，秒级
    只能渲出来才知道的（画面好不好看、动没动起来）      → 渲帧 + 像素检查，十几秒
    只能靠看的（构图合不合意、像不像那么回事）          → 模型看图评审，几十秒

**越便宜的检查越要往前放**：省下的不只是时间，还有"跑到一半才发现"的挫败。

## 廿五、重画也要比稿（生成侧的"改坏了"）

**现象**：生图体检发现页 10 构图不合格（主体只占 13%×16%），于是带着修正要求重画。
重画出来的**更差** —— Flow 画成了"一张竖着的纸卡浮在灰底上"，碗更小，
右边还多出一大块灰底（成片那一帧看着像个渲染 bug，其实是图的底色）。

**根因**：`do_image_audit` 重画之后**直接覆盖**了原图，没有留旧版、也没有比。
修正提示词里那句"最下面 18% 留空"，模型理解成了"把主体缩到一张更小的纸上"，
于是画了个"纸卡" —— 要求本身没错，**执行跑偏了**，而我看不到，因为旧版已经没了。

**这跟导演回路里早就踩过的坑一模一样**：
> 「每轮存档 + 打分 + 只保留最高分版（实测模型改坏过两次）」

代码那条腿早就有比稿，**图的这条腿没有** —— 同一个教训在两条腿上各踩了一次。

**改法**（下次动这块时照做）：
1. 重画写**新文件**（`10_2.png`），不覆盖 `10_1.png`；
2. 两版都量一遍，按同一套判据（主体位置 + 大小）**取好的那版**；
3. 两版都不合格就把两版都摆出来给人看，别自己默默挑一个。

**一句话**：**任何"改"，都要留旧版、要比。** 不管改的是代码还是图。

## 廿六、验收要"逐页过"，不能只看出片成功

成片渲完 → 拼接成功 → 文件在、时长对 —— 这些**都对了**，
但每页好不好看是另一回事。这次做了 `tools/accept_film.py`：

- 每页在**中间偏后**抽一帧（避开开头的揭示/运动中间态）
- 机器判三件：是不是黑页、是不是空页、**字幕带里有没有字**
- 26 帧拼成一张验收表，人一眼扫完

**判据写成阈值，人只看表**：亮度 < 18 报"黑页"，细节 < 0.4% 报"空页"，
字幕带细节 < 0.4% 报"字幕带没字"。
（实测：页 15 亮度只有 66 —— 但那是"夜里那扇门"，本来就该暗，看表就明白了。
阈值只负责**把人引到该看的地方**，不负责下结论。）

**为什么值得**：349 秒的片子人不可能一秒一秒看完，
但"26 页每页都对"这件事必须验 —— 抽帧 + 拼表把这件事压到一分钟。

## 廿七、后端的 stdout 断掉会变成"半死"

**现象**：服务在跑、`GET /api/projects` 正常，但**任何会报错的请求都不返回**
（浏览器里是 `ERR_EMPTY_RESPONSE`，脚本里是 `RemoteDisconnected`）。
表现特别像"这个路由不存在"，其实是**错误处理那一行 `print()` 挂了**：

```python
except Exception as e:
    print(f"[err] POST {u.path}\n{tb}", flush=True)   # ← 管道断了，这一行抛异常
    return self._err(500, ...)                        # ← 永远走不到
```

**根因**：起服务的那个终端被关掉/重启，进程还在，但 **stdout 的管道已经断了**。
于是 `print` 抛 `OSError`，异常处理自己成了新的异常，连接直接断。

**修法**：让服务把日志写进**文件**，不要依赖管道 ——

    python app\server.py --port 8777 *> logs\server.log

文件句柄不会因为终端没了就断。

**怎么一眼认出来**：服务"活着但请求断连"+ 日志里看不到 `[err]` 行，就是这一类。
（正常的 500 会在响应体里带 `{"error": ...}`；断连则什么都没有。）

## 廿八、Flow + bsk 自动化：把"挂参考图"跑通踩的五个坑

目标是让 Flow **照着定妆图**生成角色（跨图形象一致）。路上连踩五个，全部实测确认。

### ① 窗口必须最大化 —— 不然按钮被响应式折叠掉

**现象**：`bsk observe` 只看到 13 个按钮，`Add ingredients` 点了没反应/找不到菜单项。
**根因**：Flow 是响应式布局，窗口一小就**把一整排按钮折叠进 overflow**，连 ARIA 树里都没有。
**解法**：开完会话第一件事就放窗口：

```bash
bsk window resize --session <sid> --width 1600 --height 900
```

**效果**：同样的页面，元素从 13 个变成 25 个 —— 冒出来 `Characters`、`Scenes`、`Agent`、
`Start generation`（之前只能靠 aria-label 摸到）。
**结论：驱动任何现代 Web 应用之前，先把窗口放大。**（用户提醒的，一试就灵）

### ② `[has-submenu]` 的按钮：菜单开在**新图层**，必须重新 observe

**现象**：点 `Add ingredients to the prompt box [has-submenu]`，然后找菜单项 —— 一个都没有。
**根因**：observe 输出第一行是 `@layers N`。点完这类按钮，菜单渲染在**新的图层**里，
旧快照里当然没有；而且 ref 会**重新编号**（上一轮的 `@e13` 在这一轮可能是别的元素）。
**解法**：**点完必须重新 observe**，然后在新快照里找菜单项：

```
点 @e13（Add ingredients）→ 重新 observe → 找到 @e5 button "Upload media" → 对它做 upload
```

### ③ bsk 不肯"猜"目标 —— 别给它 CSS 选择器

**现象**：`bsk upload --mode drop --selector '[contenteditable=true]'` 报
`the file-drop target could not be safely resolved`；`--mode input` 直指按钮报
`the upload trigger did not activate a file input`。
**根因**：它**故意**不接受"看起来像"的目标 —— 宁可失败也不投错地方（这是对的设计，节省了我们排错）。
它的提示写得很直白：**"rerun observe and select the … itself; do not guess another target"**。
**解法**：一律先 `bsk observe`，拿 `@eN` ref，再 `--ref @eN`。

### ④ 文件输入被 Chrome 拦：扩展要开 "Allow access to file URLs"

**现象**：

```json
{ "code": "cdp_failed", "message": "{\"code\":-32000,\"message\":\"Not allowed\"}",
  "hint": "check that BrowserSkill has Chrome's 'Allow access to file URLs' permission; otherwise use `bsk request-help`",
  "data": { "phase": "set_files", "reason": "set_file_input_failed" } }
```

**根因**：`DOM.setFileInputFiles` 这类操作需要**扩展有读本地文件的权限**（`chrome://extensions` →
BrowserSkill → 详情 → "允许访问文件网址"）。
**解法**：让用户在扩展页打开那个开关（一次性）；或者用 `bsk request-help` 让人来点文件选择器。
**判据**：报错 `phase: set_files` + `Not allowed` 就是这一条，别去怀疑选择器或页面。

### ⑤ Flow 自带 `Characters`（角色）—— 先找它的原生功能，别自己造

窗口放大后侧栏露出 `All media / Characters / Scenes`。**Characters 就是它自带的"角色一致性"**：
建一次角色、跨图复用。我们要的正是这个，比"每次挂参考图"更稳。
**教训**：**先翻一遍人家 UI 里的功能清单，再决定要不要自己写流程**（跟"先翻上游的 safe 概念"是同一条）。

### ⑥ 这一条现在卡在"一个 Chrome 开关"上（2026-10-16 状态）

三条路（`Add ingredients` → `Upload media`、`Characters` → `Upload`、直接对按钮 upload）
**全部**在同一处被拦：

    { "code": "cdp_failed", "message": "Not allowed",
      "data": { "phase": "set_files", "reason": "set_file_input_failed" } }

要开的是：**`chrome://extensions` → BrowserSkill → 详情 → 「允许访问文件网址」**。
开了之后上面的代码不用改，`flowgen.attach()` 直接就能用（路径已经打通，只差这一下）。
**判据**：只要看到 `phase: set_files` + `Not allowed`，就是权限，不是选择器、不是页面。

### ⑦ Flow 的 `Characters` 面板长什么样 + **它是生图还是生视频**（2026-10-16 核实）

点侧栏 `Characters` → **"New character — Build and reuse characters for consistent videos"**，三个入口：

| 入口 | 说明 |
|---|---|
| `Describe your character…` 文本框 | 纯文字描述建角色（空着时 `Start generation` 是 disabled，提示 "Prompt must be provided"） |
| `Add ingredients to the prompt box` | 挂参考图（has-submenu，同上） |
| **`Upload`** | **直接传图片** ← 最直接的一条 |
| `Add from project` | 从项目已有素材里选 |

还有 6 个预设性格（The Eccentric / Professional / Wildcard / Familiar / Wicked / Fantastical）。

**它的模型家族下拉只有三个，全是生图模型：**
`🍌 Nano Banana Pro` · `🍌 Nano Banana 2 Lite` · `🍌 Nano Banana 2.1` —— **没有 Veo、没有视频模型**。

> **一条硬规矩（用户提的）**：**我们只用 Flow 生图，绝不用它生视频。**
> 生图（Nano Banana）不花积分；生视频（Veo）要花积分，不划算。
> 自动化脚本里凡是能看到 `crop_16_9` / `Nano Banana` / `x1` 这组设置的地方，
> 都确认是**图片**侧；不要点任何带 `Veo` / `video` 字样的东西。



## 廿九、edge-tts 接进 TypeScript 项目的三个坑

### ① 默认只发整句时间戳 —— 必须 `boundary='WordBoundary'`

edge-tts 7.x 的 `Communicate(text, voice)` **默认 `boundary='SentenceBoundary'`**，
中文只会给**整句一个时间戳**，画面就没法按字对齐（`P.cw` 直接废掉）。
写 `boundary='WordBoundary'` 之后：24 个字 → 12 条词级区间（"反而 0.10→0.40"、"表面的和平 3.97→5.09"）。

### ② 中文别走 stdin/stdout 管道 —— 写 UTF-8 文件、传路径

**现象**：桥脚本从 stdin 读 JSON，报 `NoAudioReceived: No audio was received`（像是音色名错）。
**根因**：**Windows 控制台管道按 GBK 编码**，PowerShell 塞进去的中文到 Python 那边已经是乱码；
参数（argv）也一样受 ANSI 码页影响。
**解法**：请求写成 **UTF-8 的 JSON 文件**，只把**文件路径**（纯 ASCII）当参数传。
**一句话**：跨语言调用时，**中文永远走文件，不走管道和命令行参数**。

### ③ 偶发抖动是常态 —— 退避重试，并区分"可重试/别重试"

**现象**：同一个请求，连试三次：失败 → 成功 → 成功。报错尾巴里能看到 `Sec-MS-GEC` 之类的 URL。
**解法**：桥里退避重试（1.5s / 3s / 4.5s），**并且区分**：
音色名写错、文本为空 → 直接抛（重试白搭）；网络/403 → 标记 `retryable` 让上层再试。

## 三十、素材读取：它会"判"但不会"报"（缺口就是这么漏的）

**现象**：喂一份扫描件 PDF，界面一切正常，直到发现片子里什么都没讲。
**根因**：`materials.ts` **早就**有扫描件判定（`SPARSE_CHARS_PER_PAGE = 40`），
解析结果里也带 `warning`。但 `runner.ts` 只在**解析彻底失败**时报错（`!f.parsedTo`），
"解析成功但内容近 0 字"这条路**一声不吭**。
**解法**（我们的补法）：
1. `materialVerdict(f)` → `ok / empty / sparse`，判定集中在一处；
2. **出片前把判定报给用户**（带字数、页数、原因、**可照抄的补救命令**）；
3. `ocr-scan.py`：扫描件逐页渲图 → **视觉模型转写** → 写成**同格式**的 `<名>.pdf.md`。
   实测 3 页扫描件 / 13 秒 / 211 字，**一个字不差**。
**教训**：**"算出了风险"和"让人知道"是两件事**。有判定没出口 = 没有判定。

## 卅一、在这里干活的操作纪律（都是被坑出来的）

| 坑 | 现象 | 规矩 |
|---|---|---|
| **PowerShell 引号** | 中文串里再嵌双引号 → `ParserError: UnexpectedToken`（本次会话踩了 7 次） | **长命令一律写成文件**（`.py` / `.mjs`），别在命令行里拼中文+引号 |
| **中文路径** | 用 `endswith('docs/方案.md')` 比对 `git ls-files` 输出会假失败 | git 默认 `core.quotepath=true` 会把中文转义 → 先 `git config core.quotepath false` |
| **junction 会被遍历** | 数"工程目录多大"时把 `engine_modules`（junction）当普通目录走进去，凭空多出 200MB | 统计前先排除 junction；Windows 上用 `mklink /J` 建、`rmdir` 删（不删目标） |
| **嵌套 .git 会丢文件** | 把带 `.git` 的目录放进另一个仓库，外层只记一个 `160000` gitlink（**文件一个都没进仓**） | 放进外层仓库前先删内层 `.git`，或者当 submodule 正式管 |
| **subprocess 编解码** | `text=True` 时 cmd 的 GBK 输出会崩线程 | 一律 `encoding="utf-8", errors="replace"`，并设 `PYTHONUTF8=1` |
| **依赖装一次就够** | 每次 `uv run --with X` 都要解析一遍 | 常用依赖建固定 venv（`~/.frametell/edge-venv`），只在缺的时候回退到 `uv run --with` |
| **静态检查前置** | 改完十几处再编译，错误一次全冒出来 | 改完立刻 `pnpm --filter ... build`；TS 的类型错误会**逐个点名**还有哪些地方用了旧类型（很好用） |

## 卅三、这台机器的网络要**分区对待**：三个 GitHub 域名三种命

别把"GitHub 通不通"当成一个问题，它是**三个**：

| 域 | 实测行为 | 该怎么用 |
|---|---|---|
| `api.github.com` | **稳定**（0.23s，一直好） | **所有 GitHub 读取都走它**：`/contents`（返回 base64）、`/releases/assets/{id}` + `Accept: application/octet-stream` |
| `github.com` | **时通时断**（连上要 4.7s，失败率约 2/3） | `git clone` / `push` **必须写重试**（本次 clone 第 3 次才成功） |
| `raw.githubusercontent.com` | **基本不通**（http=000） | 别用 `irm ... \| iex` 这类安装脚本；源码改从 api 的 `/contents` 取 |

**大文件走代理**：`https://ghfast.top/https://github.com/...`

| 源 | 实测速度 |
|---|---|
| `ghfast.top` 代理 GitHub | **507 KB/s** |
| `gh-proxy.com` 代理 GitHub | 90 KB/s |
| gyan.dev 直连 | 27 KB/s |
| **华为云 / npmmirror / dl.google.com** | **1.2–1.5 MB/s** |

**教训**：**国内机器上，"官方源"和"快源"经常不是同一个**。下载前先花 20 秒测速（`curl -r 0-2097152 -w "%{speed_download}"`），比闷头下 100MB 强。

## 卅四、`ffmpeg-static` 的 postinstall 在国内必挂（一句话解法）

**现象**：`pnpm install` 前面 375 个包都好好的，最后炸：
```
.../node_modules/ffmpeg-static install: Error: connect ETIMEDOUT 20.205.243.166:443
ELIFECYCLE  Command failed with exit code 1.
```
（`20.205.243.166` 就是 github.com）

**根因**：`ffmpeg-static` 的 `install.js` 默认从
`https://github.com/eugeneware/ffmpeg-static/releases/download` 下二进制。
**这是独立于 npm registry 的第二次网络请求** —— registry 走得通，不代表它装得上。

**解法**：它读三个环境变量（定义在它自己 `package.json` 的 `ffmpeg-static` 段里）：
```
binary-release-tag-env-var : FFMPEG_BINARY_RELEASE   （当前值 b6.1.1）
binaries-url-env-var       : FFMPEG_BINARIES_URL
binary-path-env-var        : FFMPEG_BIN
```
拼接规则是 `${FFMPEG_BINARIES_URL}/${release}/${executable}-${platform}-${arch}.gz`，
而 **npmmirror 上有同构的目录**，所以只要一句：
```powershell
$env:FFMPEG_BINARIES_URL = 'https://registry.npmmirror.com/-/binary/ffmpeg-static'
```
（实测对应 `ffmpeg-static/b6.1.1/ffmpeg-win32-x64.gz`，结构完全对得上；装完 35.8 秒、exit=0）

**教训**：以后看到 `ELIFECYCLE Command failed`、失败行带 `install$` / `postinstall$`，
**先看它连的是哪个域名**，别去怀疑版本或权限。

## 卅九、**能用内置 provider，就别写自定义 provider**（本批最值钱的一条）

**现象**：把 OpenCode Go 配成"自定义 OpenAI 兼容服务商"（`custom` 段），
三样验收全部 **HTTP 400**：

```json
{"type":"error","error":{"type":"MissingSessionID",
 "message":"Request is missing x-opencode-session and cannot be routed efficiently."}}
```

**根因**：`packages/models/src/custom.ts` 里的 `customProvider()` 用的是**裸的**
`openAICompletionsApi()`；而 pi-ai 内置的 `opencode-go` provider 是
`withOpenCodeSessionHeader(openAICompletionsApi())` —— **多包了一层，自动带会话头**。

```js
// node_modules/@earendil-works/pi-ai/dist/providers/opencode-go.js
api: {
  "openai-completions": withOpenCodeSessionHeader(openAICompletionsApi()),   // ← 内置的带
}
// packages/models/src/custom.ts
api: cfg.protocol === 'anthropic' ? anthropicMessagesApi() : openAICompletionsApi(),  // ← 我们的不带
```

**更亏的是**：自定义 provider 还会**丢掉一整套正确元数据**。同一个模型，两边定义差这么多：

| 字段 | 内置 provider（正确） | 我们瞎写的 custom |
|---|---|---|
| `baseUrl` | `https://opencode.ai/zen/go/v1` | `https://opencode.ai/inference/go/openai/v1` |
| `contextWindow` | **1,000,000** | 128,000 |
| `maxTokens` | **384,000** | 32,000（`custom.ts` 里硬编码的）|
| `compat` | `thinkingFormat:"deepseek"`、`requiresReasoningContentOnAssistantMessages` 等 6 项 | **全缺** |
| 图片缩放限制 | 2000px / 4.5MB / JPEG 80 | 无 |
| 会话头 | ✅ 自动 | ❌ 没有 → 400 |

**解法**：**直接挂内置 provider 的 id**，一行都不用自己写：

```jsonc
{
  "keys": { "opencode-go": "oc_sk_…" },          // ← 用内置 provider 的 id
  "defaults": { "model": "opencode-go/deepseek-v4.1-flash", "runtime": "pi" }
}
```

`catalog.ts` 第 108 行是 `builtinModels({ credentials })` —— **FRAMETELL 本来就加载了 pi-ai
的全部内置 provider**，我们要做的只是把 key 挂到正确的 id 上。

**验完的结果**（三样全通）：

```
① 文本              PASS   '测试通过'                        72 tokens
② function calling  PASS   get_weather → {"city": "北京"}
③ 看图 (vision)     PASS   '一只手正在掀开/捏着纸张一角，中间偏右'
```

> **纪律（和"先翻上游"是同一条）**：**配任何模型/provider 之前，先翻一遍
> `node_modules/@earendil-works/pi-ai/dist/providers/data/*.json`。**
> 里面是作者校过的正确答案 —— baseUrl、contextWindow、compat、图片限制全都有。
> 自己拼配置 = 把人家调好的东西一项一项猜错。

## 四十三、Clash 退出但系统代理还指着它 → 整个浏览器白屏

**现象**：`https://opencode.ai/console` 打开是**空白页**。

**排查过程**（三步见底）：

| 步 | 怎么查 | 结果 |
|---|---|---|
| 1 | `curl -w "%{http_code}" https://opencode.ai/console` | **200** —— 站点是好的 |
| 2 | 看 DNS 解析 | 解析到 **`198.18.0.9`** —— 保留地址段，说明有代理在做 fake-ip |
| 3 | 查代理进程 + 端口 + 注册表 | **`mihomo.exe` 已退出，7890/7891 无人监听**，但 `ProxyEnable=1` |

**根因**：Clash Party 进程死了，Windows 系统代理**还指着 `127.0.0.1:7890`**。
浏览器所有请求发往一个没人接的端口 → 白屏。

```
curl -x http://127.0.0.1:7890 https://opencode.ai/...
  → curl: (7) Failed to connect to 127.0.0.1 port 7890
```

**排查口诀**：**"网站白屏"先分清是"站点坏了"还是"本机出不去"** ——
`curl` 直连能过，就一定是本机代理/网络栈的问题，别去怀疑人家网站。

**两条附带结论**：
1. **opencode.ai 直连就行，不需要代理**（实测 0.84 秒）。
2. Clash 这类工具退出时**不一定**会清掉系统代理，`ProxyEnable` 要自己确认一次。

## 四十五、**同一个 Chrome 目录下有两个版本的可执行文件**（改名的那个不会被更新）

**现象**：扩展商店说"**当前浏览器版本不兼容**"。
明明刚把 Chrome 从 109 升到了 155（注册表、`chrome.exe` 都验过），扩展却仍说不兼容。

**根因**：这个 Chrome 是**被改过名的便携版**，`Bin\` 下同时躺着**两个不同版本**的主程序：

```
Bin\chrome.exe             155.0.8059.85   ← MSI 只更新这个（它认识的"标准文件名"）
Bin\chrome_proxy.exe       155.0.8059.85
Bin\Google Chrome.exe      109.0.5414.120  ← 改名的那个，MSI 根本不管它
Bin\109.0.5414.120\        旧版本目录（残骸）
Bin\155.0.8059.85\         新版本目录
```

而**快捷方式指向的是改名的那个**：

| 快捷方式 | 指向 | 版本 |
|---|---|---|
| 桌面 `The - Chrome`（用户日常用） | `Google Chrome.exe --profile-directory="Profile 2"` | ❌ 109 |
| 开始菜单 `Google Chrome` | `Google Chrome.exe --user-data-dir=…` | ❌ 109 |
| 公共桌面 `Google Chrome` | `chrome.exe` | ✅ 155 |

**所以"升级成功"和"用户实际跑的是新版"是两件事。**
只看注册表版本 / 只看 `chrome.exe` 的版本 → 会得出"已经升好了"的错误结论。

**排查口诀（升级浏览器类问题必背）**：

```
① 注册表/安装包版本      → 它"装"了哪个版本
② 每个同名 exe 的版本    → 目录里到底有几个不同的版本   ← 这次栽在这
③ 快捷方式的 TargetPath  → 用户"启动"的是哪一个
④ 运行中进程的 .Path     → 实际跑的是哪个（终极依据）
```

**解法**（**不用关浏览器**就能做）：Windows 允许**重命名正在运行的程序**，只要不覆盖它：

```powershell
# 1) 把旧的重命名走（运行中也能改名）
Rename-Item 'Bin\Google Chrome.exe' -NewName 'Google Chrome.exe.109.bak'
# 2) 把新版复制成原来的名字（新文件，不与运行中的冲突）
Copy-Item 'Bin\chrome.exe' 'Bin\Google Chrome.exe'
# 3) 验证
(Get-Item 'Bin\Google Chrome.exe').VersionInfo.ProductVersion   # → 155.0.8059.85
```

这样**三个快捷方式一次性全好**，且旧版留了备份（`.109.bak`）。
用户只需**关掉再打开** Chrome。

**教训**：**改过名的软件，自动更新会漏掉它。**
凡是"明明更新了却没生效"，先看**目录里是不是有好几个同名不同版本的副本**，
再看**快捷方式到底指向哪一个**。

> 这也是卅六节那条的续集：那次是"扩展根本没装"，这次是"浏览器版本看着像升了、其实是另一个 exe"。
> **同一条纪律：别靠印象，把每一层都用一条命令验死。**

## 四十六、Chrome 扩展是**按 Profile 隔离**的（跨账号时最容易翻车的一条）

**现象**：在 Profile 2（thequi81）里装好并 `bsk doctor` 验通的 BrowserSkill，
切到真正要用的 Profile 3（nishinon857 / nanase）之后，`bsk status` 又是 `browsers: []`。

**根因**：Chrome 的扩展**按 Profile 隔离**。同一个用户数据目录下，
**Profile 2 装了 ≠ Profile 3 有**。前面"扩展已装好"的结论，对另一个 Profile **无效**。

**判据（一条命令把每个 Profile 都验死）**：

```powershell
$ud = "$env:LOCALAPPDATA\Google\Chrome\User Data"
foreach ($prof in 'Profile 2','Profile 3') {
  $j = Get-Content "$ud\$prof\Secure Preferences" -Raw -Encoding UTF8 | ConvertFrom-Json
  $ids = @($j.extensions.settings.PSObject.Properties) | Where-Object { $_.Name } |
         Select-Object -ExpandProperty Name
  "{0}: BrowserSkill={1}" -f $prof, ($ids -contains 'hhcmgoofomhgciiibhipgmgkgnoenaoi')
}
```

**顺带摸清：怎么知道"当前活动的是哪个 Profile"**

| 线索 | 位置 |
|---|---|
| `profile.last_used` / `last_active_profiles` | `User Data\Local State` |
| **命令行有没有 `--profile-directory`** | **没有**时 → Chrome 打开"上次使用的那个" |
| 每个进程的 `--profile-directory` 分布 | 可能是清一色 `(none)`，别指望它 |

**教训**：**"扩展装好了"必须附带"装在哪个 Profile"**。
换账号/换 Profile 之后，**第一件事是重新验扩展在不在**，别拿旧结论当数。

## 四十七、驱动现代 Web 应用前，窗口要**撑得比屏幕还大**

**现象**：`bsk observe` 只看到 13 个按钮；`Add ingredients` 点了没反应/找不到菜单项。
**根因**：Flow 是响应式布局，**窗口一小就把一整排按钮折叠进 overflow**，连 ARIA 树里都没有。

**这次的额外细节**：本机屏幕只有 **1366×768** —— 所以"放大"必须**故意超过屏幕**：

```powershell
bsk window resize --session <sid> --width 1600 --height 900
```

窗口设成 1600×900（比屏幕宽）→ Chrome 就按 **1600 的视口**渲染 → 按钮不再被折叠。
（`bsk window` **只有 `resize`，没有 `maximize`** —— 所以"最大化"要用**超屏尺寸**来等效实现。）

**怎么确认生效**：`bsk observe` 里**元素数量**会明显变多（本次实测 13 → 25）。

**纪律（写死）**：**开完会话的第一条命令就是撑窗口**，不是"先看看，不行再撑"。
这条和廿八节①是同一个坑，这次把阈值说清楚了：**要比屏幕大**。

## 四十八、Flow 的地区判定是**两层**：文档层看 IP，应用层看账号

**现象**：换到美国节点后，`curl` 走同一代理访问 Flow 是 **200**，
但浏览器里仍然是 `flow.google.com/unsupported-country`。

**用 `bsk debug` 抓请求后，两层分得很清楚**：

| 层 | 表现 | 判据 |
|---|---|---|
| **第一层：文档层（看 IP）** | 香港节点时，**文档请求直接被重定向**到 `/unsupported-country` | 纯 IP 判定 |
| **第二层：应用层（看账号）** | 美国节点时，**文档 200 正常加载**、应用启动、发出 7 个 `batchexecute` RPC（**全 200**），**之后才客户端跳转** | 后端告诉应用"这个账号不服务" |

**决定性对照**（同一代理、同一 URL、同一时刻）：

```
命令行 curl（无 cookie）        → 服务器放行，最终 URL 就是项目页，http=200
浏览器（带登录态 cookie）        → /unsupported-country
```
⇒ **第二层卡的是账号，不是 IP。**

```

电话      178 7666 2927        ← 中国手机号

付款资料   pay.google.com/gp/w/u/0/home/settings → 直接跳 /home/signup（根本没建）
```

换成 `nishinon857@gmail.com`（nanase）后，**同一浏览器、同一节点、同一 URL，Flow 正常**。

**排查顺序（照这个走，省时间）**：

1. **先看节点地区** —— 香港/澳门这类 Google 明确不支持的，文档层就被拦
2. **再看用的是哪个 Google 账号** —— 关联手机号/邮箱/付款资料会决定"账号国家"
3. **最后才怀疑代理链路** —— 而且要**在浏览器里**量出口 IP

## 四十九、bsk 会话寿命短：把「建会话 → 操作」串成一条命令

**现象**：`bsk session start` 之后隔几条命令再操作，报
`session not registered or already stopped`。本次会话里**失效了 4 次**。

**原因**：Agent Window 被关闭、浏览器重启、或换 Profile，都会让 session 失效。

**做法**：
- 把 **建会话 → 撑窗口 → 导航 → 取证/截图** 写在**同一条命令**里，别跨命令依赖 `$sid`
- 真要用 `$sid` 时，先 `bsk status --json` 看 `sessions` 里还在不在

**顺带**：`bsk session start --json` 的 id 字段是 **`session_id`**（不是 `id`）。
字段名猜错时 `$sid` 会是空，后面所有命令一起报 `--session` 缺值 —— **看着像命令写错，其实是解析错**。

## 五十、bsk 抓包**默认脱敏响应体**，别指望它给你看后端返回

**现象**：`bsk debug request <id> --part response` 拿到的 body 是：

```json
{ "state": "omitted", "reason": "unparsed_json", "text": "", "redacted": true }
```

**结论**：`bsk debug` 能告诉你**请求发了什么、状态码是多少**（这次正是靠它定位到
"文档 200 + 7 个 RPC 全 200 之后才跳转"这种关键分层），
但**响应体读不到**；要看 body 得换路子（页面内 `fetch`、或 `bsk evaluate`）。

**所以它的定位是**：**判断"问题出在哪一层"，不是"后端到底说了什么"。**

**取值路径的小抄**（字段名容易猜错）：

```
bsk debug request <id> --part response --json
  → .request.response_body      ← 不是 .response
  → .request.response_body.text / .state / .reason / .redacted
```

## 五十四、Flow 的菜单是**瞬时的**：点开 → observe → 动作 必须写在**一条命令**里

**现象**：`click 'More options'` 之后再**单独**一条命令去 `evaluate` 找 `Download`，

**解法**：三步串成**同一条命令**：

```

## 五十五、PowerShell 给 bsk 传 JS：**外层双引号 + JS 内层单引号**

**踩了两次的坑**（本次）：

| 写法 | 结果 |
|---|---|
| 外层**单引号** + JS 里用双引号 | ❌ **内层双引号被吃掉** → `ReferenceError: menuitem is not defined`（`[role=menuitem]` 变成裸词）|
| 外层**双引号** + JS 里**只用单引号** | ✅ 正常 |

规律：**PowerShell 给原生命令传参时会把内层双引号剥掉**。
所以写 `bsk evaluate` 的 JS：**外层用 `"`、JS 内部一律用 `'`**，且 JS 里**别出现 `$`**（会被插值）。

**另一条**：`@e14` 这类 ref **必须加引号**（写 `'@e14'`）——
不加会被 PowerShell 当成 **splatting**，报 `missing target: pass <ref-or-selector>`。
**看着像 bsk 的错，其实是 shell 的错。**

```

## 五十九、把 Flow 生成流程**脚本化**时踩的 4 个坑（2026-10-18）

把「挂角色 → 写提示词 → 生成 → 等 → 下载」写成一个 PowerShell 脚本批量跑（16 张），连踩四个：

| # | 现象 | 真因 | 修法 |
|---|---|---|---|
| 1 | 脚本里的中文全乱 | **`.ps1` 没 BOM，PowerShell 5.1 按 GBK 读** | 存成 **UTF-8 with BOM**：<br>`[IO.File]::WriteAllText($f, $c, (New-Object Text.UTF8Encoding($true)))` |
| 2 | "找不到 Add ingredients" | 按钮的 `textContent` **只是图标名**（`add`），真标签在 **`aria-label`** | 搜索时两个都拼上：<br>`(e.getAttribute('aria-label')||'')+' '+(e.textContent||'')` |
| 3 | 还是"找不到" | 提示框是 **`position: fixed`** —— 里面元素的 **`offsetParent` 是 `null`**，被我的"可见性检查"全滤掉了 | 可见性改用 **`e.getClientRects().length > 0`** |
| 4 | 角色选不中 / 等到超时 | ① 菜单项文本是 **`小树Character`（没有空格）**，且**必须限定 `[role=option]`**（否则命中侧栏同名按钮）<br>② `-match 'true'` 撞上 JSON 里的 **`"ok": true`** → "生成中"**恒为真**，循环永不退出 | ① 只搜角色名 + `-Scope '[role=option]'`<br>② 精确匹配 `'"value": "true"'` |

### ⚠️ 但真正让前几次失败的原因不是上面任何一个

**是会话又被空闲停掉了** —— `evaluate` 返回 `session not registered`，
而我的判断写成了"没找到元素"，于是**白查了半天正则和选择器**（还错改了两处代码）。

**教训（四十九节的加强版）**：
- 判断"元素没找到"之前，**先确认会话还活着**（`evaluate "1"` 是否返回正常）
- **别把"命令失败"和"条件不满足"混成一个分支** —— 前者要报错重连，后者才是重试
- 批量任务要把**整条流程（含几十秒的等待）封在同一个进程**里跑，别跨命令

### 判定"生成完成"别依赖图片计数

CDK 虚拟滚动 + 懒加载会让 `img` 计数飘（离屏的 `naturalWidth` 变 0）。
**实测最稳的是**：点完生成**固定等 80 秒**，然后**靠"能不能下载到"兜底重试**（失败再等 20 秒，最多 3 次）。
16 张连跑 **零失败**，每张约 100 秒。

## 五十七、Clash 切到**规则模式**后，git 连不上 GitHub（要单独配代理）

**现象**：`git push` 连续 3 次
```
fatal: unable to access 'https://github.com/...': Failed to connect to github.com:443
```
但**浏览器能正常访问 GitHub**。

**诊断（一条命令分清）**：

| 测法 | 结果 |
|---|---|
| `curl --noproxy '*' https://github.com` | **`000`**（20 秒超时）|
| `curl -x http://127.0.0.1:7890 https://github.com` | **`200`**（0.43 秒）|
| `git config --get http.proxy` | **空** |

**根因**：Clash 在**规则模式**下，走的是**系统代理**（浏览器遵守，所以浏览器没事）；
但 **git 自己读 `http.proxy` 配置，不读 Windows 系统代理** —— 于是它直连，而这台机器直连 GitHub 不通。

**解法**（只影响 github，不污染其他域名）：

```powershell
git config --global http.https://github.com.proxy http://127.0.0.1:7890
```

**顺带澄清一条容易混的**（文档第一批第 1 条记过）：
> "命令行不读系统代理，浏览器读" —— **git 也是命令行**，所以它同样不读。
> 凡是命令行工具连不上、浏览器却正常，**先查它自己的 proxy 配置**。

**代价**：Clash 没开时 git 会报代理连接失败（而不是超时）——但两种情况都是失败，
**所以这条可以常驻**，不用每次手动加 `-c http.proxy=`。

## 六十、Flow 批量生图：取图环节的四个坑（2026-10-19，全部实测）

> 背景：用 Flow 批量生成 12 张处境图（挂 `小树`/`小芽` 角色 chip）。
> 第一轮 12 张"成功 5 张"，其中 **2 张根本不是提示词画的** —— 是把项目里的老图当新图抓回来了。
> 修完的代码在 `app/flowgen.py`（`generate()` / `_fetch_raw()` / `baseline_sigs()` / `_full_bases()`），
> 批量脚本在 `tools/gen_scenes.py`。

### 坑① 尺寸写在 URL 后缀里，同一张图先后是两副面孔

```
…/asb/ANqvLOYo…=s512-rw     ← 网格里的缩略图（512×512）
…/asb/ANqvLOYo…=s1600-rw    ← 同一张图的原图（1376×768）
```

- 生成完**先出现缩略图**，过一会儿才换成原图。老代码"等新 URL + 取回来看宽度"会**只拿到缩略图**，
  报"新图都是缩略图尺寸，没收到大图"。
- **修法**：认图**按 base 去重**（`u.replace(/=s\d+(-rw)?$/,'')`），取图**自己拼 `=s1600-rw`**。
  要小图（比如算指纹）就拼 `=s128-rw` —— 快、省流量。

### 坑② 项目里的老图会被当成"新图"（吃掉两张，最隐蔽）

网格是**虚拟滚动 + 懒加载**：生成动作会让布局重排，**离屏的老图趁机补加载**，
于是"生成前后的 URL 差集"里混进老图 —— 谁排前面就抓谁（`sorted()` 的结果还不一定是新图）。

- 本批次受害：`p06`（要 SIM 卡，抓回"长桌+空椅"）、`p24`（要小芽攥纸，抓回"男孩站在门前"），
  两张都是**用户在 Flow 里早先就生成过的图**。
- **两道保险，都要上**：
  1. **基线要滚全**：进项目后 `window.scrollTo` 分 10 次滚到底取**并集**
     （读一次永远取不全 —— 离屏的会被卸载）。
  2. **指纹比对**：把已知图拉成 128px 小图，算 **16×16 灰度指纹**；
     新抓到的图跟基线比 **平均绝对差 ≤ 6** 就判"这是老图"，扔掉继续等。
     （同一份原始文件差 ≈ 0；不同轮次画的图，再像也差得远。）
- 附带一条：`generate()` 收完图要把新图**记进基线**，否则下一张会把它当老图扔掉。

### 坑③ 生成完之后，输入框会消失一会儿

现象：连着生成时，下一张报 `提示词没输进去：{'ok': False, 'reason': 'no input'}`。
真因：一张出完，**Flow 会把提示框收掉**（大概是"出图中"那个状态），这时页面上一个
`[contenteditable]` 都没有。

- **修法**：写提示词前**轮询等输入框回来**（10 次 × 6 秒），等到了再写。
- 别把它跟"会话被停掉"混为一谈（那是 `session not registered`，见五十九节）——
  **两种"没输入框"要分别报错**。

### 坑④ 输入框不清空，新提示词会接在旧的后面

`execCommand('insertText')` 是**插入**不是替换。生成完 Flow 有时留着上一句，
直接写就变成"两句拼一起"，出来的图是两件事揉在一起。

- **修法**：`el.focus()` → `execCommand('selectAll')` → `execCommand('delete')` → 再 `insertText`。
- 写完**读回文本核对**（`textContent` 里必须包含整句提示词）——写错一次 = 白等 60–100 秒。

### 补充：角色 chip 怎么确认（它没有文字标签）

chip 是**一个 img**（角色的素材缩略图），`innerText` 里**找不到角色名** ——
所以"挂完读一下附近文字里有没有'小树'"这种检查**必然误报**。
**判据**：提示框容器里 img 的数量（挂之前 0、挂之后 ≥1），身份靠**截图人工过一眼**
（本批次截图在 `experiments/uitest/flow/attach-小树.png` / `attach-小芽.png`）。

## 六一、把"页代码"跑成片子：工程挂载、字幕、验收（2026-10-19）

> 背景：26 页整片（`projects/emotion-full`，9 分 52 秒）。这一节是**从页代码到成片**那一公里的实操。

### ① 新工程要先跟引擎"接上"（junction）

`packages/engine/tools/project.mjs` 的 `linkProject(dir)` 会在工程目录里建两个 junction：
`engine/`（引擎本体）、`engine_modules/`（浏览器依赖）。**没挂就会 `failed to load .../engine/boot.js`**。

```powershell
cd experiments/frametell-src/frametell-main
node -e "import('./packages/engine/tools/project.mjs').then(m=>m.linkProject('D:/WorkSpace/video-factory/projects/emotion-full'))"
```

`.gitignore` 里要有 `engine` / `engine_modules`（链接是每台机器自己建的，不入库）。

### ② 三个工具的用法与分工

| 工具 | 要不要浏览器 | 干什么 | 注意 |
|---|---|---|---|
| `lint.mjs` | 不用 | 语法 + 逐页扫，报 `sparse page`（主体太小） | 在**工程目录**里跑；缺图会 `failed to load`，不影响其余判断 |
| `snap.mjs` | 用 | 抽帧/对照表 | `[--only p01,p02] [--subs] --sheet 名字`，后面跟的是**整片全局秒**（不是页内秒） |
| `render.mjs` | 用 | 分段渲染（约 12 路并行）→ 配音混音 → 带字幕版 → 拼接 | **META.voice 的片子，每条 cue 都必须有音频**，缺一条直接报错退出 |

### ③ 字幕切行的根因在 **cue**，不在切分器

`script.mjs` 的 `splitCue` 只会在两处切：**标点处**、**攒满 `SUB_MAX`（默认 12）**。
所以判据是：**cue 里第 12 个字之前必须有一个标点**，否则就是硬切 ——
实测把"支付工具"切成"支 / 付工具"、"类型"切成"类 / 型"。

- 写台词时就按这条写；写完全是硬切也没关系，在自然处补个逗号就行（TTS 停顿也更自然）
- 改完跑 `tools/check_cues.py`（目标：**0 条硬切**）
- 31 条一次修完的记录在 `tools/fix_cues_commas.py`（改了什么一目了然）

### ④ `voice.js` 的契约（`d` / `o` / `k`）—— 配音这一步的说明书

```js
SCRIPT.VOICE = { speaker, provider, pages: [[{t, f, d, o, k}, …], …] }
```

| 字段 | 含义 | 踩过的点 |
|---|---|---|
| `t` | 这条 cue 的文字 | **必须和 script.js 一字不差**；对不上这条就当没配音（退回按字数估算） |
| `f` | 音频文件（相对工程目录） | 用 `.wav`（48k 双声道），ffmpeg 直接吃 |
| `d` | 这条音频的长度 | **停顿要自己补进音频里**：句号 0.5s / 逗号 0.28s / 页末 0.25s。<br>引擎在"有 `o`"这条路里**不再自己加停顿**，节奏全靠 `d` |
| `o` | 开头那段静音（speech 真正起声的位置） | 引擎用它算 `cue.start = ct + o`；音频本身从 `ct` 开始播 |
| `k` | 逐字起声（相对音频开头，**一个字一个数**） | 字幕与画面按字对齐就靠它；长度对不上会静默退回估算 |

**做完这三件事才算配音完成**：`tools/make_voice.py`（合成）→ `script.mjs`（出口播脚本 + 字幕）→ `render.mjs`（混音进片）。
改了 cue 文字**必须重配音**（`make_voice.py` 的缓存按文字校验，改了会自动重做那一条）。

### ⑤ 抽帧看片才是验收的眼睛

`tools/qc_snap.py`：26 页按 22% / 55% / 85% 各抽一帧，拼成两张对照表
（`--pages p01,p04` 只看几页；`--subs` 带上字幕看）。

**看这两张表能立刻抓出三类毛病**（本次各抓到一处）：
1. **暗图配深色字** —— 页 04 是夜景图却按"日间主题"渲染，`ink` 深色标签在暗底上看不见 → 该页改 `setTheme('night')`
2. **光飘在空角落** —— `P.light` 摆在没主体的地方就是一团圆圈 → 把光挪到桌上/门上/物件上
3. **主体太小** —— `lint` 的 `sparse page` 警告 + 抽帧都能看出来 → 用"收紧机位"（cam 起始 `z` 1.2+）裁进来

### ⑥ 一条工程纪律：**图不复制**

页面里直接写 `../scene-library/xxx.png`（相对路径，`P.scene` 照样吃）。
好处：图库是唯一出处，改一张库里所有引用它的页一起变；仓库不重复存图。

## 六二、片长是**先定的**，不是写完才知道（2026-10-19 返工教训）

第一部 26 页写完 9 分 52 秒，用户一句"时间太长了"。**返工要重配全部配音 + 重渲**，代价一整天。
所以新片的顺序反过来：

```
先定片长 → 反推字数 → 再写字
   实测换算：194 字/分钟（≈4.2 字/秒 + 停顿）
   6 分钟 ≈ 1200 字；8 分钟 ≈ 1550 字；10 分钟 ≈ 1900 字
```

**片长由三样叠出来，写的时候就要心里有数**：

| 来源 | 量级 | 怎么调 |
|---|---|---|
| 台词字数 | ~4.3 字/秒 | 少写就是在省时间 |
| **停顿（补在音频末尾）** | 184 条 × 0.3 秒 ≈ **55 秒** | `tools/make_voice.py` 的 `TAIL`（句号 0.5→0.35、逗号 0.28→0.20）|
| 语速 | `RATE` 每 5% ≈ 全片 ±5% | 同上（-8% → -4%）|

第一部的 592 秒里，**光停顿就占 55 秒**、语速偏慢又多十几秒 —— 这两样加起来够砍掉一分半，
不用删一个字。

**默认值已调成紧的**（`RATE=-4`、句号 0.35 / 逗号 0.20）—— 下一页片子直接就是这个节奏。

**换题材要复用的东西**（别重建）：引擎与风格包、`小树`/`小芽` 两个角色（Flow 里挂着 chip 用）、
处境图库（先翻能复用的，缺的才生成）、三条工具链（`gen_scenes` / `make_pages` / `make_voice`）
+ 验收两件（`qc_snap` / `accept_emotion`）。开工手册：`docs/新题材开工手册.md`；
一键建工程：`python tools/new_film.py <名字> --title "…" --minutes 6`。

## 六三、这台机器跑整片渲染的**硬上限**：4 核 / 8G（2026-10-19 实测）

机器：Lenovo 20AL（2 核 4 线程 / 8G / **页面文件只有 512MB** / Intel 核显 / 三星 860 EVO SSD / 走远程桌面）。
第一部片的"整片渲染"在这台机器上**没跑成**，实测三条：

| 事实 | 数据 | 说明 |
|---|---|---|
| 默认并行把机器拖爆 | `render.mjs` 默认 **12 路**（每路一个 Chrome + ffmpeg）；跑了近一小时，**148 段一段没完成** | 4 线程扛不住 12 个 Chrome |
| 机器被拖到硬重启 | 21:21 系统事件 **Kernel-Power 41**（8/22 也有一次） | 不是软件崩，是整机非正常断电/重启 |
| 段缓存一开始"永远为 0" | `--plan` 显示 `0/148 reused`：因为**从没有一段真正完成** | chunks 里只有 `.jobs-*.json` 和 `.part.mp4` |

**浏览器要先钉死**：引擎 `bins.mjs` 找 Chrome 只认标准路径（`Program Files\...` 与
`AppData\Local\Google\Chrome\Application\chrome.exe`），本机 Chrome 在
**`AppData\Local\Google\Chrome\Bin\chrome.exe`**（同源问题见四十五那条），`CHROME_PATH` 又没设 ——
"到底哪个浏览器在画"必须先验证（**单段冒烟**），否则并行度调多低都白搭。

**这台机器上的正确跑法**（不换机器就这么跑）：
1. 渲染固定 `--workers 2`；
2. 先设 `CHROME_PATH` 指向本机 chrome.exe + 单段冒烟（约 2 分钟）；
3. 用引擎自带的 `--segments` **分批**画（每批 20–30 段，5–8 分钟一批）——配合"完成的段进缓存"，
   崩了/重启了只丢当前批，天然断点续跑；
4. 渲染期间不开 Flow 的浏览器（素材/出片**分时**复用这台机器）；
5. 页面文件调到 4–8GB（SSD 空闲 118G）；还不行就换机器渲（引擎支持 `--plan`/`--segments` 跨机分片）。

一句话：**不是"4 核不能渲"，是"12 路并行 + 浏览器没找对 + 512MB 页面文件"三件事叠起来把老机器拖到重启。**
