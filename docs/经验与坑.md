# 经验与坑 · video-factory

按时间倒序。每条都写上「现象 → 根因 → 怎么修 → 以后怎么防」。
只记**实测撞到过**的，不记猜测。

---

## 一、平台与环境的坑

### 1. 命令行不读系统代理，浏览器读

**现象**：Chrome 能打开 Flow 和 Gemini，但 `curl` / Python 下载东西一律超时；
HuggingFace 下不了模型；Flow 的图床 `flow-content.google` 返回 `http_code=000`。

**根因**：这台机器在 `HKCU\...\Internet Settings` 里设了系统代理 `127.0.0.1:17890`。
Chrome 读它，命令行工具默认**不读**（只看 `HTTP_PROXY`/`HTTPS_PROXY` 环境变量）。

**怎么修**：脚本里显式设环境变量，或者从注册表读出来（`tools/transcribe.py` 里的
`use_system_proxy()` 就是干这个）。

**以后**：任何要联网的脚本，先问一句「浏览器能通吗」。能通就是代理问题。

### 2. Windows 下中文 JSON 的编码

**现象**：`render.py` 读 spec 直接崩，`UnicodeDecodeError: 'gbk' codec can't decode`。

**根因**：Python 的 `Path.read_text()` 不带 encoding 时用系统区域编码（中文 Windows 是 GBK），
而仓库里的 JSON 是 UTF-8。

**怎么修**：所有子进程注入 `PYTHONUTF8=1`。上游代码一行不改。

**反噬（重要）**：`PYTHONUTF8=1` 之后，**`subprocess.run(text=True)` 默认用 UTF-8 解码**，
而 Windows 的 `cmd` / PowerShell 吐的是 GBK。于是 `cmd /c mklink` 的输出解码崩掉，
**把整个请求线程打挂**，请求永远不返回（不是慢，是死了）。

**以后**：**每一个** `subprocess.run(..., text=True)` 都要写 `encoding="utf-8", errors="replace"`。
本项目 15 处全加了。

### 3. PowerShell 的 `ConvertTo-Json` 会把长字符串包成对象

**现象**：服务收到 `{"script": {"value": "...", "PSPath": "..."}}`，而不是一个字符串。

**根因**：`Get-Content -Raw` 返回的字符串带着扩展属性（PSPath、ReadCount 等），
PS 5.1 的 `ConvertTo-Json` 把属性一起序列化。

**怎么修**：发送前 `[string]$s` 强转成纯字符串。

**教训不只是"改测试脚本"**：它暴露了应用缺**信任边界上的类型校验**。现在有 `text.text_field()`：
能认 `{value: ...}` 这种形状，真不是文本就明确报错，不让它一路崩到后面去。

### 4. 目录联接（junction）可以零拷贝把项目挂进引擎

**背景**：上游引擎只认自己根目录下的 `demos/<名>/`，而我们的项目要放在 `projects/`。
复制整个引擎太重（几十 MB × 每个项目）。

**做法**：`cmd /c mklink /J` 建目录联接（**不需要管理员**，符号链接才需要）。

**坑**：`Path.resolve()` 会把联接解析成真实路径，于是「路径越界检查」判定
`engine/demos/<项目>` 跑出了 `engine/` → 403。改成用 `os.path.abspath` 做**字面**归一化，
不跟随链接。

## 二、架构上的坑

### 5. 长调用不能同步等

**现象**：点「切成页面」之后请求挂满 25 分钟不返回，会话被拖死。

**根因**：三层叠加 ——
① LLM 调用是同步的，前端死等；
② 没有总超时；
③ 私有 opencode server 会跟着桌面版服务重启一起死，而代码**只在第一次调用时探活**。

**怎么修**：
- 所有长调用改成**后台任务**（和渲染同一套队列），提交立刻返回 job id，前端轮询。
  实测提交耗时从 25 分钟变成 **0.1 秒**。
- `LLM.TIMEOUT = 240`，超了明确报错。
- `generate()` **每次调用前**探活，不健康就重建私有 server。

### 6. 引擎的"拒绝渲染"是好事，但要会读

上游引擎在场景代码出错时**拒绝启动**（不静默出空白帧），这是对的。
但它把错误写在 `[page] BOOT FAILED` 里，需要从子进程 stdout 捞出来看。

实际撞到的：`02: 文件里没有 SCENES['02'] = { draw(c, lt, t) }`。

## 三、提示词的坑（最值钱的一类）

### 7. 契约里的占位符要真的替换掉

**现象**：模型写的场景文件注册成 `SCENES['p02_window_paper']`，引擎按 id `02` 找不到，拒绝渲染。

**根因**：引擎契约那段是共享常量，里面写的是字面量 `SCENES['<镜号>']`，
而页号是通过另一个参数传的，**模型从没被告知"注册名必须精确是 02"**。

**怎么修**：两处 ——
- 契约里改成 `__SHOT__` 占位，发提示词前 `.replace("__SHOT__", sid)`；并且明写
  「注册名必须精确是 `SCENES['02']`」
- **写盘前做确定性校验**：只有一个注册名但不是目标名，就地改回；其余情况直接报错。

**教训**：提示词里的**契约性字面量**（注册名、文件名、路径）是硬约束，
不能留占位符让模型自己猜。而且**每一处都要配一条确定性校验兜底**。

### 8. 模型把引号写进字符串，JSON 被撑破

**现象**：评审明明返回了完整结构，解析却报「模型没有返回合法 JSON」，
于是一整轮回路白跑（渲染、看图都花了钱）。

**根因**：模型在字符串值里用了裸引号：

```
"…违反"不发光、单笔触"的画风锁"
```

**怎么修**（三层兜底，`app/text.py`）：
1. `extract_json` 正常解析
2. 失败 → `repair_json` 扫一遍，把「不在 key/值边界上的引号」转义掉
   （边界判断：引号后面第一个非空白字符是 `: , } ]` 之一 → 它是收尾引号；否则是裸引号）
3. 还失败 → `loose_fields` 用正则把 `score` / `ok` / `problems` / `fixes` 抠出来

同时在评审提示词里明写「字符串里不要用引号」。

**教训**：**凡是让模型输出结构化数据，都要准备容错解析**。模型偶尔会在字符串里放
引号、换行、代码块围栏，纯 `json.loads` 不够。

### 9. 重跑切页必须挪走旧场景

**现象**：重跑「切成页面」换了页列表（标题都变了），但 `scenes/` 里的旧代码还在，
`sync_eras` 照样把它们排进时间轴 —— **观众看到的是上一代页面的画面**。

**怎么修**：
- 重跑切页时把 `scenes/*.js` 挪到 `scenes_old/<时间戳>/`（挪不是删，要找回还有）
- 给每一页加**指纹**：写场景时把当时设定（标题/画面/旁白/时长/镜头/屏上字）的
  sha1 前 10 位记进 `shot['sceneHash']`；页的设定改了，接口就返回 `stale: true`，
  界面把那一页标黄，提醒要重写

**教训**：**任何"按 A 生成 B"的关系，都要能判断 B 是不是还配得上 A。**

### 10. 窄窗口下三栏会挤成一团

**现象**：`300px | 1fr | 340px` 的固定宽度，在 763px 宽的窗口里把中间栏压成 100px，
画风预设一行只放得下两个。

**怎么修**：加一条媒体查询，`max-width: 980px` 时改成上下堆叠。

**教训**：三栏布局的固定宽度之和，不能超过常见窗口宽度的一半。

### 8. 让模型"自由发挥"分镜，等于没有分镜

**现象**：让模型自由切分，切出 35 个镜头、**全都是 6 秒**，节奏完全平；
标题是画面描述（"一部手机"）而不是论点。

**怎么修**：先定**叙事骨架**再切页。情感内容用
`提问 → 案例 → 共性 → 拆解 → 建议`（模型自己演化成
`钩子 → 案例一/二/三 → 反直觉结论 → 真相拆解 → 行动建议 → 落点`）。

**效果对比**（同一份 2310 字文案）：

| | 自由发挥 | 叙事骨架 |
|---|---|---|
| 页数 | 35 | 28 |
| 每页时长 | 全是 6 秒 | 10-17 秒，平均 13.4 |
| 标题 | 画面描述 | **论点** |
| 旁白对齐 | 无 | **100%**（16 段一字不丢） |
| 贯穿意象 | 手机（普通） | **一张纸 + 一道裂缝**（来自原文"窗户纸"） |

### 9. 页要够长（学 FRAMETELL）

**现象**：一镜 2-8 秒是"快切片"的逻辑。解说/口播片不一样：**一个知识点 = 一页 = 10-15 秒**，
页内靠元素依次出现撑节奏。

**做法**：提示词里要求"一页至少 4 个先后发生的事件，用 `lt` 依次揭开"。

### 10. 风格预设不是模板库，是「画风描述 + 色板」

**现象**：一开始把 35 种艺术风格 + 8 种语法全摆出来给用户选——43 个选项，普通人没法用。

**做法（学 FRAMETELL）**：收成 6 个命名预设，每个 = 名字 + 一句人话 + 画风一句话 + 一套色板。
色板**直接用上游 `references/色板.md` 的 8 套现成色板**，不另造色（免得踩蓝紫禁区）。

选中后写进项目的是 `look / palette / character` 三个字段，**场景代码由模型按这三个字段现写**。

## 四、流程上的坑

### 11. 改哪一页，一定要清哪一页的旧帧

**现象**：评审说「第 3、5 帧主体变成窗框」——但这一镜只该有 3 帧。
上一版（时长 14 秒）留下的两帧还在目录里，评审在**混两代画面**。

**根因**：`/api/stills` 不清目录（导演回路里清了，API 那条漏了）。

**怎么修**：渲帧前先删 `t*.png`。另外加了一条守卫：**帧比代码旧就拒绝评审**
（说明上一次渲染失败了），否则会给出假分数 —— 实测分数从 4 掉到 3，
其实评的是上一版画面。

**教训**：任何"读中间产物"的环节，都要检查**新鲜度**。

### 12. 改坏了是常态，必须比稿

**实测记录（同一个模型、同一套提示词）**：

| 场景 | 结果 |
|---|---|
| 沙漏，第 1 次改 | **改坏**（沙漏放大到出画、底盖挪进玻璃中间） |
| 沙漏，第 2 次改 | 改好（7 分 → 8 分） |
| 第 02 页，第 1 次改 | **改坏**（分数 4 → 3） |

**结论**：不能信任单次修改。导演回路必须**每轮存档 + 打分 + 最后只保留得分最高的那版**。

### 13. 评审是可靠的，"改"是不可靠的

**现象**：评审**每一轮**都能挑出 5-6 条具体问题，带位置、带颜色值、带改法，
而且都是真的。但模型改不动它们 —— 下轮还是同样的几类。

**反复出现的五类**（每一页都中）：

1. 色相越界 / 渐变 / 柔光（"那块土黄不在色板里"）
2. 形状越界（"裂缝压在下边框线上、伸进阴影里"）
3. 线宽不统一（"框线比裂缝粗好几倍，等于两套笔触"）
4. 构图空（"主体挤在右侧 x=3/4，左半边整片空白"）
5. 该"停"的镜头在动（"第 1→2 帧纸的倾角变了"）

**这是最有价值的一条**：这五类里有一半**根本不用看图**，脚本就能查。

## 五、从 anatomy 学到的（另一个技能，做等距技术图的）

来源：https://github.com/wheresryan22/anatomy

### 14. Measure, then look（先量，再看）

它有两道**确定性检查**，跑不过不许交付：

```sh
node build.mjs --audit          # 必须打印 audit passed，每项失败计数为 0
node scripts/lines.mjs page.html # 必须打印 line ends: 0
```

它的原话：

> **靠眼睛修一个特写**：手调遮挡键或挪一个路点直到某张截图看着对，会破坏另一帧。
> Raptor 的手调键在 1× 下看着没问题，**有 323 处遮挡顺序错误**。
> **Measure, then look.**

**对我们的意义**：画质验证不能只有"模型看图"，必须有"脚本量数"。

### 15. 对象即解释（对情感内容极其对症）

> **不要画框框、箭头、标签。发明一个真实的物，它的运作本身就是那个概念。**

它的两种失败模式："太抽象"（浮动板块代表"层"）、"太空洞"（大平面加几条线）。

**实测我们做到了**：原文一句"不把这个**窗户纸**捅破"，被切成 10 页共用一个物
（一张纸 + 一道裂缝）：按住 → 裂开 → 划线 → 压平 → 撕成两半 → 抓住两端 →
推进麻药 → 重新对齐。

### 16. 构图有个数字标尺

它写「主体居中，占卡片 **55–65%**」。
我们的评审说「沙漏只占 36%」—— 正好对上。**这个数字可以直接进评审提示词。**

## 六、确定性与非确定性检查的边界（最终结论）

写了两层检查，各自验过：

| | 能抓 | 抓不到 |
|---|---|---|
| `scene_lint`（读代码，秒级） | 渐变、`Math.random`、显式线宽档数、有没有填底、色值字面量 | **计算出来的**线宽；混合色 |
| `frame_audit`（量帧，秒级） | 新色相、构图框太小、重心偏移、帧差（该停没停 / 画面死了） | 「主体太细读不出」「像随手画的」这类语义判断 |

**实测反例**：评审一眼看出「主体太小、像随手画的 3」，
而 `frame_audit` 报「内容框 63%×84%、重心居中，通过」。

**所以：两条腿互相替代不了。**
- 确定性检查抓**规则性违反** —— 快、免费、100% 召回，但不懂语义
- 模型看图抓**语义和可读性** —— 慢、要钱，但能抓本质

**正确用法是协同，顺序按成本排**：

```
写代码
  → scene_lint（秒级）    红灯就改，不渲、不评
  → 渲帧（10s）
  → frame_audit（秒级）   红灯就改，不评
  → 模型看图（40s，花钱）
  → 按意见改 → 比稿留最高分
```

### 色板纪律的正确规则

**不是**「渲出来的颜色必须精确在色板里」—— 那会把抗锯齿边缘和允许的明暗层次全报成错。

上游 `references/色板.md` 的原话是：「**加减明暗、透明度可以，别引入新色相**」。

所以 `frame_audit` 查的是**色相**（饱和度 ≥0.25 且亮度 ≥40 的像素，
色相离所有色板色相都超过 35° 才算越界）。

两个额外要处理的：
- 近黑像素的色相没有意义（抗锯齿会把它算成新色相），要加亮度下限
- 阈值要按"一块看得见的区域"定，不是按总面积。实测一个占全画面 0.2% 的土黄块，
  人一眼就看见，而总面积阈值会放过它。改成**分格**（3×3），任一格超过 0.1% 就报

## 九、2026-10-15 当天进展快照

**已跑通（端到端）**
- 文案 → 叙事骨架 → 页列表（28 页 / 356 秒 / 旁白 100% 对齐）
- 页 → 场景代码 → 渲染 → 两层检查 → 模型评审 → 比稿 → 回滚最优版
- 界面上：六套画风预设、骨架条（带每段页数）、页列表（带代码状态点）、
  连续预览、任务队列、下一步签字按钮
- 用 bsk 在真浏览器里点过一遍，元素齐、状态对

**关键数字**
- 切页：79.5 秒（26 页）／138.5 秒（28 页，带画风锁）
- 写一页场景代码：130 秒（长输出要放宽到 420 秒超时，240 会误杀）
- 评审一次：24-40 秒
- 改一次代码：100-200 秒（**失败率高，有硬超时兜底**）
- 导演回路 3 轮（含一次超时）：500 秒
- 渲 3 帧：10 秒
- 一条 5.9 分钟的片子若每页都跑 2 轮回路 → **约 4 小时**（需要并行才实用）

**提示词迭代记录（第 02 页，一轮一版）**

| 版本 | 得分 | 提示词改了什么 | 结果 |
|---|---|---|---|
| v1 | 6/10 | （无构图约束） | 纸小、裂缝带刺像蕨叶 |
| v2 | 5/10 | 加「主体连载体占 55-65%」「单一笔触、不许加刺」 | **纸大了，但裂缝反而相对更小**（70%→35%），且形状换身份 |
| v3 | 6/10 | 把「主角」和「载体」分开：主角自己占画面 45%+；形状全页保持同一身份；明写不许渐变/描粗边/柔光 | **对了**：裂缝是一条干净的带分叉细线，从底长到顶；静态检查 + 像素检查全过 |

**v3 之后评审提的问题变细了**（纸太小 → 分叉末端断在纸面中央、缺铅笔顿挫、字幕抢重心），
说明回路在往细处收敛。

**又一处自相矛盾（已修）**：评审要「线宽 1.5-2.5 像素随机扰动、不透明度抖动」（手绘铅笔感），
而我写的是「全画面只用一档线宽」，把它逼成了等宽矢量描边，反而更假。
**「同一支笔」不等于「等宽」** —— 一支铅笔本来就有粗细顿挫。
提示词已改成：全画面像同一支笔画出来的（允许自然扰动），要避免的是那**两套笔触**。

**一条元教训**：我扫一眼并排图觉得「新版明显更好」，评审逐帧量出「裂缝长度从 70% 掉到 35%、
第 2 帧是黑三角第 3 帧变细线、颜色跨帧不一致」。
**人对画面的快速判断不如逐帧评审可靠** —— 别用自己的直觉去否定评审的结论，
要么量数，要么把两版并排到同一张图上逐帧看。

**另一条**：三次评审给的分数是 6 → 5 → 6，但**画面质量是单调变好的**。
说明分数有 ±1 的噪声，**不能用单次分数判断进展**，要看它提的问题是不是在往细处走。

## 十、连续多页的坑（2026-10-15 下午，第一次跑通 3 页连播）

**跑通了**：页 01/02/03 各写代码 → 各过两层检查 → 各渲 mp4（13/11/13 秒）
→ `ffmpeg concat` 拼成 **37 秒 / 1110 帧 / 2.4 MB** 的片子。

**但发现一个真问题：同一个意象，每页长得不一样**

| | 页 01 | 页 02 | 页 03 |
|---|---|---|---|
| 裂缝 | 横向，从中间裂开 | 纵向，从底往上 | 只有一条淡压痕 |

页 01 结尾纸已经裂开了，页 02 开头又变回一张完好的纸 —— **观众会觉得倒回去了**。

**根因**：每一页的场景代码都是模型**独立**写的。提示词里只给了前一页的
**标题和位置**，没给它**画面上长什么样**。所以同一个「纸 + 裂缝」，
每页被重新发明了一次。

**这不是画风不一致，是「同一个物件的具体形状」不一致** ——
比画风不一致更隐蔽，因为单看每一页都没毛病。

**上游有现成的解法**：`window.SCENE_LIBS`。
一个项目可以有一个共享脚本，里面定义"这个世界"的东西
（那张纸、那道裂缝、那只手），每页的场景都调它。
`demos/long_scroll/lib/world.js` 就是这么组织的（长卷穿越片）。

**待做**：给每个项目生成一个 `lib/world.js`（定义贯穿意象的几何），
场景提示词要求"用 world 里的东西，不要自己重画"。

### 另一条：模型会自作主张画手

页 01 的 note 是「一只手，按住一张还没裂开的纸」，模型就真的用代码画了一只手 ——
**一坨深灰色的东西，四个短指头，读不出是手**。

PRD 里早就写了"代码画不好手，该交给生成图"，但提示词没明说，模型就自己上了。

**待做**：场景提示词里明写「note 里出现手、人、脸时，不要把代码画手当作第一选择 ——
要么改成不出现手的表达（只画纸和被压出来的形变），要么留给生成图补」。

### 一条流程上的悬案

写页 01 和页 03 的任务都报「超时失败」（420 秒），
**但两个场景文件都写出来了**，而且内容是对的（注册名正确、色板一致、能渲）。
时间戳显示文件是在任务报失败之后 35 秒写的。

怀疑是：`opencode api post` 那一层超时被杀，但**服务端的生成还在继续**，
某个路径把结果落盘了。没查清。**暂时按"超时后要去确认文件在不在"处理。**

**还没解决**
- 整片 28 页的完整出片（渲染全部页 → 拼接）从来没跑过
- 低饱和度的冷色（评审抓到「投影偏冷蓝」）不在像素检查的射程内
- 「主角太细读不出」这类语义问题只能靠模型看图；**「主角尺寸」这条也许能量**，
  但需要知道"主角"是画面里的哪一块，还没想出办法

## 十七、生图自动化（bsk 驱动 Flow）踩的坑

这一段是 2026-10-15 把「读 imagePrompt → 去 Flow 生图 → 下载落盘」做成自动任务时，
连着踩出来的。每条都是"看起来对、其实没生效"，写下来省得重踩。

### 1. 点生成按钮**必须用 bsk 的真实点击**

现象：`evaluate` 里 `button.click()` 返回成功、按钮也不 `disabled`，
**但页面毫无反应**，干等 240 秒什么都没有。

根因：React 那边的处理没被触发。JS 的 `.click()` 在这个按钮上不顶用。

修法：先 `bsk observe` 拿到按钮的 ref，再 `bsk click @eNN`。
（生成按钮是个**图标按钮**，可见文字是 `arrow_forward`，
真名在 `aria-label="Start generation"` 上 —— 按文字找永远找不到。）

### 2. 认"新出的图"要按**域名**，不能按尺寸

现象：收回来一摞**彩色毛毡垫的产品图**，跟提示词毫无关系。

根因：我为了"更宽容"把过滤从 `src 含 flow-content.google` 放宽成
`naturalWidth >= 800`，于是把**界面上的广告图**一起收走了。

修法：只认 `src.includes('flow-content.google')`。
尺寸判据放到**浏览器里 fetch 回来之后**再判（`createImageBitmap` 拿真实宽高，
小于 900 的直接丢），那边才是可信的。

### 3. 图多了以后，"等不到新图"是被**懒加载**坑了

现象：批量跑到第 9 页开始，**每一页都报"240 秒内没等到新图"**，
但手动开个新会话试一次，45 秒就正常出图。

根因：项目网格里的图越积越多，新图落在**视野外**；
浏览器对 `loading="lazy"` 的图不触发加载，`naturalWidth` 一直是 0。
我的检测要求"`naturalWidth > 400` 才算数"，于是永远等不到。

修法：检测只看 `img.src`（懒加载的 img 也有 src），
**不要求已经加载完**。真正的加载交给后面的 in-page `fetch`。
（教训：**"等一个已经存在的东西"和"等一个会被渲染出来的东西"是两回事**，
判据不能依赖渲染状态。）

### 4. 首页会弹 **Agree / No thanks** 的条款弹窗

第一次跑会挡路，而且它出现的位置没有规律。
修法：进项目之前统一扫一遍 `get started / 知道了 / Agree` 三个按钮点掉。
（点 Agree 是替用户做的决定，日志里要说一声。）

### 5. 450 秒才超时的任务，要留现场

只报"240 秒没等到新图"，人只能对着这句话猜。
现在超时会把**页面文字 + 图列表 + 按钮列表**打进任务日志 ——
下一次出问题，日志自己会说。**这是排查成本最低的一步，应该一开始就做。**

## 十八、长任务不许攥着项目副本（丢更新）

**现象**：`07_1.png / 08_1.png / 10_1.png` 三个文件**都在硬盘上**，
但 `project.json` 里这三页的 `images` 字段是空的 —— 项目"不记得"图生过了。

**根因**：写场景代码要调模型（一分钟）。它开头 `store.load()` 拿了一份项目副本，
模型调用期间**生图任务往 project.json 里写了三页的 images**，
写场景的活儿最后一记 `save()` 把整份旧副本盖回去 —— 那三个字段就没了。

**修法**：加了 `store.patch_shot(name, sid, **fields)`（**现读现写**，只改几个字段），
所有落盘改走它。**规矩：任务里不许跨模型调用持有项目副本。**

**以后怎么防**：任何"读 → 想很久 → 写"的流程都要问一句
"这段时间别人会不会也写这个文件"。会，就必须现读现改，或者上锁。
（这类 bug 特别阴：单独跑永远不出，两个任务并行才出。）

## 十九、存盘前跑一遍语法检查（50 毫秒换十几秒）

**现象**：模型写的场景文件结尾是 `}})();` —— **多一个大括号**。
不检查的话，这个错要等到**渲染抽帧**才暴露：起 Playwright、等十几秒，
报回来还是句 "Unexpected token '}'"，得人肉回去数括号。

**修法**：`app/scene_check.py`，存盘前用 `node --check` 解析一遍（node 在 `C:\Program Files\nodejs`）。
有错就带着**错误信息 + 原代码**让模型**只修那一处**（明写"别的一概不许动"），
修完再检查，还错就让任务失败。服务端写场景、导演回路改代码，两处都接上了。

**为什么值得**：这是**最便宜的确定性检查**——50 毫秒，拦掉一整轮渲染 + 评审（十几秒 + 一次模型调用）。
两条腿验证（确定性检查打头、模型看图收尾）的第一条腿就该是它。

## 二十、量出来再交给模型（"量图"）

**问题**：评审从第一页挑到第十八页，翻来覆去就那两句 ——
「主体太小」「重心偏在一侧」。这是当前画面质量的天花板。

**关键转念**：这两条**是能量出来的**。`app/checks.py` 的像素检查本来就在算
内容重心和内容框，只是过去用来"扣分"，没用来"给条件"。

于是加了 `app/measure.py`：把主图丢给模型问四个数
（主体是什么、外接框 0-1 相对坐标），**量一次存进项目**，
写场景代码时当成已知条件交出去：

    - 主体是：一只正在折叠纸的手
    - 外接框：宽 28%、高 56%，中心在 (0.86, 0.72)
    - 铺图参数：z 从 1.00 走到 1.07，fx = 1.00，fy = 0.50
      这三个数直接用，不要自己另算一套。

实测模型**照用了**（18 页里 fx/fy 和量出来的值逐个对得上）。
好处是两层的：模型不用猜构图（少一类错），而且**同一份数据被反复用**
（写代码用、体检用、以后重画也用），不会每处各飘一套。

**为什么先量再给，而不是让模型自己看图定**：
让模型"看一眼决定怎么裁"每次都会给不同的答案，同一页重跑两遍构图就不一样了。
量出来的是**死的四个数**，存下来，谁来用都一样。

### 顺着量图发现的一条硬道理：构图歪是**裁不回来**的

我一开始想当然：主体偏右，那把画面往左推一点不就居中了？算了一遍才明白：

`MD.cover` 的 `fx` 是"以图上哪一点为焦点"，**不是"把主体摆到中间"** ——
它的作用是让某个点落在画面的同一个相对位置，等于**保持现状**。

要把主体从 c 挪到正中，图上得有多余的料可裁，推导下来需要 `z >= 0.5 / (1 - c)`。
主体在 c=0.86 时这要求**放大 3.57 倍** —— 1376 宽的图放到 3.57 倍就是糊的。
（第一版我还把公式写错了，算出 1.56，测试用例一跑就露馅。
**这种事必须拿几个已知答案的用例验一遍**，不能靠"看着对"。）

**所以**：
- 能给代码的只有"推近一点"（主体太小就推近，最多 1.35 倍，再多就糊）；
- **构图问题必须在生图那一步摆正** —— 于是有了"生图体检"：
  逐页量，只对不合格的页带着修正要求重画（"主体放正中央、占一半、不要孩子"），
  重画后再量一遍确认。
- 量回来发现"裁不回来"时，**代码里如实写一句**
  （`——裁不回来，这一页的构图问题只能记在生图上`），
  而不是假装推一下就当解决了。

### 顺带：确定性检查和模型评审会**互相印证**

页 01 那条，像素检查独立量出"内容重心 (0.65, 0.57)、内容框只占 37%×86%"，
模型评审说"主体压在右侧并出血" —— 一个量数值、一个说人话，说的是同一件事。
两条腿都指出来的问题，基本可以确定是真问题（不用怀疑是模型的噪声）。

反过来也验证了一次：评审说"三帧取景完全相同，缓推没体现"，
但像素检查量出帧间差异 **2.96**（阈值 1.0），
我并排看三帧也确实在推 —— **这一条是模型看走眼了**。
（阈值 1.0 到实测 2.96，余量不算大。6% 的推近本来就容易看漏。）

## 廿一、成片验收清单（"画面好看"不等于"能发"）

**起因**：整片渲完才发现 —— **既没有字幕，也没有声音**。

两条链路里根本没有这两步：`do_film` 拼完就完事，`-an`（不要音轨）；
而画面里的**屏上字**又画在画面底部，就算后加字幕也会叠在一起。

**根子上的错**：过去只在验收"画面对不对"，从来没验收过"**这条片子能不能发出去**"。
画面再好看，没字幕没声音、字还和字幕打架，就是一条不能发的片子。

**以后每次出片，照这张单子过一遍**（能自动化的都要自动化）：

| 项 | 谁来保证 |
|---|---|
| 画面：每页渲出来了、没有黑帧 / 死帧 | 帧像素检查（已有） |
| **字幕**：有字幕、时间轴对得上、烧进画面 | `app/subtitle.py`（按页 dur 累加当时间轴） |
| **字幕带**：屏上字 / 主体不许进下方 18% | 静态检查 `scene_lint` + 生图提示词 |
| **声音**：旁白混进去了（`out/旁白.m4a`） | `do_film` 里有音轨就混，没有会在日志里说明 |
| 时长 / 画幅：在目标区间（3-5 分钟、1920×1080） | 出片时打印，超了要报 |
| 页数完整：没有"跳过"的页 | `do_film` 会把缺的页列出来，不假装完整 |

**教训**：**验收标准要写在"流程"里，不能靠人临场想。**
这次是靠使用者一句"作为视频为什么没有字幕"才发现的。

## 廿二、字幕带：例子即模板，错一次会被复制二十遍

### 上游早就留了位置 —— 先翻上游，别自己造

`clip.js` 里有：

```js
const safe = { top: 0, bottom: 0, left: 0, right: 0, ...(spec.safe || {}) };
// 让开的边（px）：管线烧录字幕、平台角标要用的地方
console.warn(`... spec.safe 被忽略：字幕带可能压在字上`);
```

上游把"字幕带要留出来"这件事当成**管线契约**写在代码里，还留了一行警告。
我们从来没接上，因为**开工时没有把上游的 `safe` 概念翻一遍**。

**教训**：接手一个渲染引擎前，先把它的"契约类概念"列一遍
（safe / plate / counter / transition / PUNCH ...），
这些是上游踩过坑之后留下的位置，自己重想一遍通常是白想。

### 例子即模板

场景提示词里有一段"参考例子"。它的文字 y 写的是：

```js
LINES.forEach((s, i) => word(s, [...][i] || 0.85, 880 + i * 74));
```

**880 正好在字幕带里**（字幕带从 y=885 起）。模型把它当模板抄了 ——
26 页里 **20 页**的屏上字全在字幕带里。

**教训**：提示词里的参考例子**不是说明，是模板**。
例子里出现的每个数字都会被复制；**例子必须是"完全正确"的那一版**，
不能"先随便写个能跑的，回头再调"。写例子要跟写契约一样小心。

### 两道新检查（都是秒级、免费的）

1. **屏上字不许进字幕带**：扫"画字"那几行里的数字（模型写字位置都是字面量，
   实测 26 页全是 `fillText(s, 150, 880 + i * 74)` 这个形状），
   超过 `subtitle.safe_bottom()`（1080 上是 855）就报。
2. **做法检查**：贴图页的代码里必须真的**铺了图**（有 `MD.cover(` / `IMG[`）。
   这条抓到一个真事：页 02 被模型"重画"成了手画纸裂缝，图完全没用上（见下节）。

### 存盘前先过静态检查（最便宜的一条腿）

以前是"写完了 → 渲帧 → 评审"，静态检查只在导演回路里跑。
现在**存盘之前就先跑一遍静态检查**，没过就让模型改一轮，过了才写文件。

理由很简单：静态检查是**秒级、免费**的；渲帧 + 评审要十几秒加一次模型调用。
**根本不该把没过静态检查的代码存进去**。过了才存，后面每条链路都省一遍。

（对应地加了 `/api/lint_fix`：只按检查意见小改，不重跑整页生成。
实测整页重写 1.5-6 分钟，只改检查项 30-40 秒。）

## 廿三、`opencode run` 是个**有文件工具的 agent**（悬案破了）

**悬案**（经验与坑第 10 节记过）：写场景的任务报"超时 420 秒失败"，
**但场景文件在 35 秒后又出现了**，内容还是对的。当时没查清，"暂时按超时后去确认文件在不在处理"。

**现在搞清了**：`opencode run --standalone --model ... <提示词>` 起的是一个
**能自己调用工具的 agent**，不是纯补全。它读得懂"把这个场景文件写出来"，
于是**自己动手把文件写进了工作区** —— 我们的 Python 代码只是等它返回文本，
所以进程被超时杀掉时，文件其实已经落盘了。

**两个后果，都要防**：

1. **超时 ≠ 失败**。现在 5 页"超时失败"的代码页，文件全都是好的。
   所以超时之后**必须先看文件在不在、对不对**，再决定重跑。
2. **它可能"顺手"改别的东西**。页 02 就是这样被害的：它是贴图页
   （`mode=image`，该 `MD.cover` 铺图），却被写成了 6660 字的手画场景。
   现在有了"做法检查"能当场拦住。

**给提示词时的规矩**：明确说"只输出代码，不要动工作区里的文件"。
但要**假设它可能会动**，所以落盘之后要验（模式检查 + 语法检查 + 静态检查）。

---

## 廿四、找个静态检查器扫一遍，别靠"跑一遍才知道少了哪个 import"

**现象**：整片渲染失败两次，两次都因为同一个低级原因 —— **漏了 import**：

- 第一次：`name 'UV' is not defined`（我用的是 `jobs.py` 里的 `UV`，server.py 没引）
- 第二次：`name 'subprocess' is not defined`（`_run_sync` 里用了，顶上没 import）

代价：一次是 26 页并行渲染刚要开始就全灭；一次是白等 30 分钟的失败任务。

**修法**：`uv run --with pyflakes python -m pyflakes app/*.py` —— **两秒钟扫出全部未定义名**。
（顺手还扫出几个没用到的 import 和一个 f-string 忘了占位符。）

**规矩**：改完代码**先扫一遍再提交任务**，尤其是那种"要跑半小时才知道错了"的任务。
**用工具的检查，永远比用运行时的检查便宜。**

这条和前面几条是同一个道理的三次重演：

    能静态查的（语法、未定义名、屏上字越界、做法用没用图）→ 存盘前就查，秒级
    只能渲出来才知道的（画面好不好看、动没动起来）      → 渲帧 + 像素检查，十几秒
    只能靠看的（构图合不合意、像不像那么回事）          → 模型看图评审，几十秒

**越便宜的检查越要往前放**：省下的不只是时间，还有"跑到一半才发现"的挫败。

---

## 廿五、重画也要比稿（生成侧的"改坏了"）

**现象**：生图体检发现页 10 构图不合格（主体只占 13%×16%），于是带着修正要求重画。
重画出来的**更差** —— Flow 画成了"一张竖着的纸卡浮在灰底上"，碗更小，
右边还多出一大块灰底（成片那一帧看着像个渲染 bug，其实是图的底色）。

**根因**：`do_image_audit` 重画之后**直接覆盖**了原图，没有留旧版、也没有比。
修正提示词里那句"最下面 18% 留空"，模型理解成了"把主体缩到一张更小的纸上"，
于是画了个"纸卡" —— 要求本身没错，**执行跑偏了**，而我看不到，因为旧版已经没了。

**这跟导演回路里早就踩过的坑一模一样**：
> 「每轮存档 + 打分 + 只保留最高分版（实测模型改坏过两次）」

代码那条腿早就有比稿，**图的这条腿没有** —— 同一个教训在两条腿上各踩了一次。

**改法**（下次动这块时照做）：
1. 重画写**新文件**（`10_2.png`），不覆盖 `10_1.png`；
2. 两版都量一遍，按同一套判据（主体位置 + 大小）**取好的那版**；
3. 两版都不合格就把两版都摆出来给人看，别自己默默挑一个。

**一句话**：**任何"改"，都要留旧版、要比。** 不管改的是代码还是图。

## 廿六、验收要"逐页过"，不能只看出片成功

成片渲完 → 拼接成功 → 文件在、时长对 —— 这些**都对了**，
但每页好不好看是另一回事。这次做了 `tools/accept_film.py`：

- 每页在**中间偏后**抽一帧（避开开头的揭示/运动中间态）
- 机器判三件：是不是黑页、是不是空页、**字幕带里有没有字**
- 26 帧拼成一张验收表，人一眼扫完

**判据写成阈值，人只看表**：亮度 < 18 报"黑页"，细节 < 0.4% 报"空页"，
字幕带细节 < 0.4% 报"字幕带没字"。
（实测：页 15 亮度只有 66 —— 但那是"夜里那扇门"，本来就该暗，看表就明白了。
阈值只负责**把人引到该看的地方**，不负责下结论。）

**为什么值得**：349 秒的片子人不可能一秒一秒看完，
但"26 页每页都对"这件事必须验 —— 抽帧 + 拼表把这件事压到一分钟。

## 廿七、后端的 stdout 断掉会变成"半死"

**现象**：服务在跑、`GET /api/projects` 正常，但**任何会报错的请求都不返回**
（浏览器里是 `ERR_EMPTY_RESPONSE`，脚本里是 `RemoteDisconnected`）。
表现特别像"这个路由不存在"，其实是**错误处理那一行 `print()` 挂了**：

```python
except Exception as e:
    print(f"[err] POST {u.path}\n{tb}", flush=True)   # ← 管道断了，这一行抛异常
    return self._err(500, ...)                        # ← 永远走不到
```

**根因**：起服务的那个终端被关掉/重启，进程还在，但 **stdout 的管道已经断了**。
于是 `print` 抛 `OSError`，异常处理自己成了新的异常，连接直接断。

**修法**：让服务把日志写进**文件**，不要依赖管道 ——

    python app\server.py --port 8777 *> logs\server.log

文件句柄不会因为终端没了就断。

**怎么一眼认出来**：服务"活着但请求断连"+ 日志里看不到 `[err]` 行，就是这一类。
（正常的 500 会在响应体里带 `{"error": ...}`；断连则什么都没有。）
