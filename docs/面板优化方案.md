# 面板优化方案（照 frametell 的交互来）

> 探的是 fork 里的真东西：`packages/ui/src/views/*`（界面）、`i18n/zh/*`（中文交互文案）、
> `packages/core/src/studio.ts`（后端契约）、`packages/ui/src/lib/run.ts`（事件流怎么折成界面）。
> 结论先说：**我们的面板要照它的"信息架构 + 状态机 + 契约"重做，但流程用我们自己的**
> （我们的画面是"页表 + Flow 处境图"，它的是"agent 写页代码"）。

## 一、frametell 的交互骨架（照抄这五样）

### ① 首页：一句话开工

| 它有 | 内容 |
|---|---|
| 主题 | **一句话就够**（"讲讲番茄工作法为什么有用，讲给总是拖延的上班族"）|
| 资料 | 附 PDF/Word/PPT/EPUB/MD/图片；**也能填网页链接、GitHub、本机路径**；可拖进来 |
| 开关 | 联网调研（只给主题时默认开；附了资料默认只用资料）|
| 参数 | 时长（参考）、视频语言、风格、**导演模型 / 画页模型分开选**、配音（可试听）|
| 预估 | "预计约 N 积分" → 不够就提示充值 |
| 开头 | 「开始制作」|
| 列表 | 最近的视频：状态（**等你确认分镜** / 制作中 / 已暂停 / 已完成 / 出错了）+ 动作（**去确认分镜** / 看进度 / 继续制作 / 观看）+ 分组 + 删除 |
| 偏好 | 创作偏好（"想让每部片子都照你的习惯来？"）|

### ② 工作台：左对话 / 右画面

- 顶栏：状态、**花费明细**（模型/输入/输出/缓存命中）、**暂停 / 继续制作**、回到首页、连接中断自动重连
- 两栏：**对话（左）+ 画面（右）**；窗口窄时切成单栏（对话/画面切换）；左栏宽度**可拖、记忆**
- 状态文案："{阶段}中" / "等你确认分镜" / "正在暂停…" / "修改中" / "导出中"

### ③ 对话：过程列表 + 审批卡 + 逐页状态

- **过程按章节折**：调研 → 分镜 → 口播 → 配音 → 画面 → 全片检查 → 渲染；
  每个动作有**三态文案**（`step` 已完成 / `start` 刚开始 / `doing` 正在做）——
  例："写分镜 / 在写分镜"、"画第 3 页 / 在画第 3 页"
- **逐页一行**（因为页面是并行画的）：排队 / 正在画 · {进度} / 自己检查（第 N 遍）/
  画好了 / **画好了，有一处要你看看** / 没画出来
- **审批卡（关键）**：分镜这一步停下来，卡里给"**确认分镜，开始制作**"按钮 +
  一句提示"**要改哪里，直接在下面说**"
- 暂停说明：谁停的（用户 / 中断 / 出错），并保证"**已经做好的部分都保留着，继续不会重做，也不会重复花钱**"
- 完成卡："你的视频好了" + "**想改哪里？直接在下面说，只重画要改的那几页**，改完马上能看；要发出去时再导出 mp4"
- 导出：带字幕 / 无字幕 两个

### ④ 消息框：附件 + 引用 + 排队

- 附文件/图片（可拖、可粘贴）；"正在附上…"
- **引用**：把「第 N 页」「某一句」「某一帧」**加到对话**（`UserRef`）
- **排队**："想改什么先写下，片子做完就交给导演"（跑动中写的消息不会丢）
- 换音色：附在消息上——"发送后整片重新配音 · 画面不变"（还没配音时说"不花额外的钱"）
- 品牌素材：「套用整套品牌」= 一条预置指令

### ⑤ 画面栏：成片 / 逐页

- 两个视图：**成片**、**逐页 · N**
- **分页时间带**：可"跳到第 N 页"；每句口播跟着画面走（点一句从那里播）
- 细看一页：**这一页的关键画面** + **这一页的口播（每句带时间）** + **自检截图**（它是"导演检查这一页时看的截图"，每格左下角是成片里的时间）
- 每张页卡/每一帧都能"**加到对话**"或"**改这一页**"
- 字幕开关（字幕：开/关）+ 下载带字幕/无字幕版；Lightbox 放大看

### ⑥ 后端契约（`Studio` 类，UI 就靠这些）

```
projects() / project(id) / createProject(input, files, {start})
say(id, text, refs)            ← 人对导演说话
attach(id, name, data)         ← 附件
approve(id, feedback?)         ← 审批（可带反馈）
stop(id) / halt(id) / start(id) / export(id)
subscribe(id, since, fn)       ← 事件流（带游标，可断线续听）
timeline(id) / frames(id, times) ← 时间轴与抽帧（画面栏用）
projectFile(id, rel) / openProjectFile(id, rel)
styles() / models() / voices() / voicePreview() / settings()
```

## 二、我们现在的面板 vs 目标

| frametell 有 | 我们现在 | 差距 |
|---|---|---|
| 首页：一句话 + 资料 + 参数 | 只有一个"建片"表单（名字/标题/分钟）| ❌ 没有主题输入、没有资料、没有风格/配音/角色选择 |
| 左对话 / 右画面 | 左"日志" / 右"产物列表" | ⚠️ 位置对，内容不对：应该是**对话（过程+审批）**与**画面（逐页+成片）** |
| 过程列表（章节 + 三态）| 纯终端日志 | ❌ 要把它折成有语义的事件 |
| **审批卡** | 无（只有产物 ✓/✗）| ❌ **这是最关键的一环** —— 我们的"分镜"= **页→处境映射表** |
| 逐页状态行 | 无 | ❌ 我们天生逐页做图，正好对上 |
| 完成后改片（只重做受影响页）| 无 | ❌ |
| 引用页/句/帧进对话 | 无 | ❌ |
| 排队 / 暂停继续 | 无（按钮一点到底）| ❌ |
| 画面栏：时间带 / 逐页 / 自检截图 / 字幕开关 | 只有产物列表 + 视频 | ⚠️ 要拆成"成片 / 逐页"两个视图 |
| 花费明细 | 无（我们免费）| 🔸 改成"用时 + 图数 + 字数"即可 |

## 三、照它重做，但流程是我们自己的

**为什么不能直接用它的 studio 界面**：它的"画面"是 agent 写页代码（`pages/pNN.js` 由模型创作），
它的审批点只有"分镜"一个；我们的画面是**页表 + Flow 处境图**（人要在图这一步点头），
我们的审批点天然是三个。**交互模型一样，流程不同** —— 所以照它的信息架构重做，契约照抄（将来好合）。

**契约照抄（我们后端对 UI 的接口）**：

```
GET  /api/projects                     项目的状态 + 进度（照 workbench.status）
POST /api/projects                     建片 {topic, files[], minutes, style, voice, cast, web}
GET  /api/projects/:id/events?since=   事件流（SSE，带游标）
POST /api/projects/:id/say             {text, refs[]}   对导演说话
POST /api/projects/:id/approve         {stage, feedback?}  审批（映射表 / 图 / 成片）
POST /api/projects/:id/stop|start|export
GET  /api/projects/:id/timeline        页与句的时间轴（借引擎的 layout）
GET  /api/projects/:id/frames?t=,...   抽帧
```

**我们的阶段与审批点**（对应它的 调研/分镜/口播/配音/画面/检查/渲染）：

```
写词 → 审台词 → 【审批①页→处境映射表】→ 出图 → 【审批②每张图（通过/重画）】
   → 排页 → 配音 → 字幕 → 渲染 → 全片检查 → 【审批③成片（要不要发/改哪里）】→ 导出（带/无字幕）
```

## 四、分期实施

### P1 · 对齐骨架（先做这个，1–2 天）

1. **首页**：主题一句话 + 资料（文案文件/图片，可拖）+ 目标时长 + 风格（固定 warm-emotion）+
   配音（edge 音色列表 + 试听）+ 角色（小树/小芽）→ 「开始制作」；下面"最近的视频"（状态 + 去确认/继续/观看）
2. **工作台两栏**：左对话、右画面；窄窗切单栏；左栏可拖
3. **过程列表**：把工具输出折成事件（每步三态文案），**不再显示原始终端日志**（日志收进"展开看"）
4. **审批卡①（页→处境映射表）**：表格 + 每页"✓/✗ + 一句改法" + 「确认，开始出图」
5. **逐页状态行**：排队 / 正在生成图 / 正在画 / 好了 / 有一处要你看看 / 没出图
6. **画面栏**：逐页卡（图 + 该页口播 + 时间）+ 成片播放器 + 字幕开关

### P2 · 改片闭环

7. **引用**：页/句/帧"加到对话"；消息框附件
8. **只重做受影响页**（按页 diff：词改了 → 重配音+重渲该页；图换了 → 只重渲）
9. **排队 + 暂停/继续**（跑完当前页停下，不是砍进程）
10. **审批卡②③**（图一张张过、成片一个）

### P3 · 我们的差异化

11. **生图审批台**：Flow 生成的图在这里一张张过（通过 / 一句话改法重画），落 `docs/审批.json`
12. **自检截图位**：把 `qc_snap` 的抽帧表塞进"自检截图"
13. **素材库**：角色卡、处境图库的浏览与复用（"这张图给第 7 页用"）
14. **用量栏**：用时 / 图数 / 字数（替代它的花费）

## 五、验收判据（P1 做完怎么算过）

1. 不懂代码的人能**只看首页**把一部新片开起来（主题 + 时长 + 配音 → 开始）
2. 跑动中能看懂"现在在干什么"（过程列表三态），不需要看终端
3. **映射表审批**能在页面上完成（逐页 ✓/✗ + 写改法），点了"确认"才继续出图
4. 逐页状态能看出"哪一页出图失败"
5. 成片能在画面栏播放、字幕能开关
6. 全过程**不用手改任何文件**（这是"人在网页上生成"的底线）

> 这一版先不碰 frametell 引擎一行；等 P2 的"只重做受影响页"稳定了，
> 再评估要不要把它并进 studio（契约已对齐，届时是替换后端，不是重写界面）。

## 六、角色模块 + 素材库 + 生图队列（IP 一致性那一块）

> 用户要求：**能在 web 的素材库里选角色图，背后是在 Flow 上生成图（要 bsk 操作浏览器）**，
> 并且"整个流程要安排好"。这一节就是那块的设计。

### 6.1 三个库（素材库要分三层，别混在一起）

| 库 | 内容 | 从哪来 | 谁在用 |
|---|---|---|---|
| **角色库** | 角色卡（识别特征 + 实测色板 + 禁用项）+ 定妆图 + 已生成的各视图 | `projects/character-assets/`；Flow 里的 Character | 每一页：挂 chip 时选谁 |
| **处境图库** | 通用处境（男/女 × 8）+ 各片专用图 | `projects/scene-library/`（20 张）| 页表里"这页用哪张" |
| **本片素材** | 本片实际用到的图（含从处境库借来的） | 生图队列产出 | 逐页审阅、替换、重画 |

**每张图的卡片上要有的东西**（这是"能选"的前提）：
缩略图 · 文件名 · **属于哪个角色** · 处境一句话 · 尺寸 · **一致性指标**（留白带、嫩芽色像素）·
用在哪些页 · 状态（等审批 / 已通过 / 打回 / 是上一版）· 三个动作：**指定给某页** / **以这张为参考再生成** / **重画**

**库里现在缺一份索引**：现在是 README 手写的表 → 要变成 `projects/scene-library/index.json`
（每张图的元数据），面板读它渲染库、写它记录审批。**索引是素材库模块的地基**。

### 6.2 角色模块

**一个角色 = 两样东西**（必须成对，缺一不可）：

| 样 | 在哪 | 作用 |
|---|---|---|
| Flow 里的 `Character`（由定妆图建的） | Flow 项目 `video-factory` | **生成时挂 chip**，形象才锁得住 |
| 角色卡（识别特征 + 色板 + 禁用项） | `projects/character-assets/character-cards.md` | 写提示词、量一致性、评审都靠它 |

**面板上要能做的事**：
1. **看**：角色卡 + 定妆图 + 这个角色已生成的所有图（按处境分组）
2. **选**：本片用哪几个角色（第一部：小树=男 / 小芽=女）；每页指定谁
3. **量**：每张新图自动量一致性（尺寸 / 下方留白 / **嫩芽色 `#DEF0A8` 有没有** / 发色偏暖还是偏冷）→ 不合格标红
4. **加角色**（将来加第三个 IP）：上传 2–3 张定妆图 → **bsk 走 Flow 的建角色流程**（这步的 UI 路径我还没实测，
   方案里标成"待实测"，不吹）→ 生成锚点图 → 自动量出色板 → 写进角色卡

### 6.3 生图队列（"选好角色 → 背后在 Flow 上生成"）

**一次生成 = 一条任务**，字段：

```json
{ "id": "p07-1", "page": "p07", "cast": "小树",
  "scene": "男孩低着头，一根食指反复掐着纸上同一道折痕，侧光打在手和纸上",
  "out": "p07-crease.png",
  "status": "queued|browser|prompt|generating|fetching|saved|review|failed",
  "tries": 1, "error": "", "img": "p07-crease.png",
  "metrics": { "w": 1376, "h": 768, "band_std": 1, "sprout_px": 52 },
  "at": "2026-10-19 12:31:02" }
```

**队列落在片子里**：`projects/<片>/gen-queue.json`（人写的、面板写的、执行器读写的都是这一份）。
**文件即队列** —— 面板重启、执行器重启都不丢活，断点续跑（目标文件已存在就跳过，这条已在用）。

**状态机**（面板上就显示这个）：

```
queued 排队 → browser 开浏览器/进项目 → prompt 挂角色+写词（读回核对）
→ generating 生成中（约 60–100 秒）→ fetching 取原图（挡住老图：指纹比对）
→ saved 入库（转 PNG + 量一致性）→ review 等审批 ──✓──→ approved 可用于排页
                                             └─✗(写改法)→ queued（重排队，同页最多 3 次）
```

**执行器（独立进程，不在面板里）**：`tools/gen_worker.py`
- 串行跑（Flow 一次只做一张），一张一个会话；同一角色连续多张可复用会话（但"生成完输入框会消失"要轮询等它回来）
- 每张都做：**挂 chip → 截图存档**（事后核对挂的是谁）→ 清空+写词 → **读回核对** → 生成 → 取图 → 指纹挡老图 → 落盘 → 量一致性 → 写状态
- 失败分类记录（会话掉 / 输入框没回来 / 老图误判 / 网络），**失败不连坐**（记录 + 继续下一张）
- 每张写一条 jsonl（`batch-c-log.jsonl` 已经在做这件事）
- **面板只做两件事**：往队列里写任务、读队列状态渲染

**为什么执行器要独立**：生图是"几十分钟的活"，面板是"网页"。面板里跑长任务 = 一刷新就断、
一崩就丢。**面板 = 遥控器，执行器 = 干活的人**。

### 6.4 bsk 那一段的前置条件（面板要有"环境自检"按钮）

照 frametell 的 `env(): EnvCheck[]`，我们的清单：

| 检查 | 判据 | 不通过怎么办 |
|---|---|---|
| bsk daemon | `bsk status` 有 daemon_version | 面板给一行命令（`bsk daemon start`）|
| 扩展连着 | `bsk doctor` 里 `extension connected` | 提示装/开扩展，并指明**要装在登录 Flow 的那个 Chrome Profile** |
| Chrome 能进 Flow 项目 | 打开项目页 + 有输入框 | 提示登录 / 换代理节点（地区不可用会报 `unsupported-country`）|
| 设置是生图模型 | Flow 设置里 Image = **Nano Banana 2.1**（免费）| 面板提示；**永远不碰视频模型**（花积分）|
| 角色在不在 | Characters 面板里能看到 `小树` / `小芽` | 提示去建（或走 6.2 的加角色流程）|
| 本地链 | ffmpeg / edge-venv / 磁盘空间 | 提示 |

自检不通过就别入队 —— **省掉"排队 20 分钟才发现浏览器没连"**。

### 6.5 面板上的样子

- **素材库页**（新 tab）：三个库分栏；图片卡按 6.1 的字段；拖到右侧页卡 = "这页用这张"
- **页卡上加两个按钮**：「换图」（从库里挑 / 让它去生成一张）与「改这一页」（引用进对话）
- **生图任务面板**：队列列表（每行 = 状态机 + 缩略图 + 重试按钮）；同一屏能看到"现在在生成第 3/7 张"
- **审批位**：`review` 状态的图在对话里也出一条卡（"第 7 页的图好了，要你看看"），点了 ✓ 才进排页

### 6.6 分期（并进前面的 P1/P2/P3）

| 期 | 角色/素材库这块做什么 |
|---|---|
| **P1** | 素材库页（读 `scene-library/index.json`，三库分栏、图片卡、指定给页）+ 角色卡展示 + **环境自检** |
| **P1.5** | **生图队列 + 执行器**（`gen-queue.json` + `gen_worker.py`）+ 队列面板 + 审批位（✓/✗/重画）|
| **P2** | "以这张为参考再生成"、"换角色重生成、只重渲受影响页"、把队列接进"改片对话"（引用一张图 → 自动入队）|
| **P3** | 加角色流程（上传定妆图 → bsk 建 Character → 自动量色板 → 写角色卡）、素材库的搜索/标签 |

### 6.7 这块的验收判据

1. 在素材库里能**一眼看出每张图是哪个角色的**，并把它指定给某一页（不用碰文件）
2. 点「生成」后，**面板能看到任务排队/进行/成功**，全程不用看终端
3. 生成完的图**自动出现在库里且带一致性指标**；不合格的能一键重画（改法写在框里）
4. 环境没准备好时**不让入队**，并说清缺哪一步（含"扩展装在哪个 Chrome Profile"）
5. 面板关掉再开、执行器崩了再起，**队列状态不丢**（文件即队列）
