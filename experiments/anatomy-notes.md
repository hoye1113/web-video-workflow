# 竞品拆解 · anatomy（wheresryan22/anatomy）

来源：https://github.com/wheresryan22/anatomy ｜ MIT ｜ 作者给 Claude Code / Codex / OpenCode 用的技能

## 它是什么（和我们的根本差异）

**它做的是交互式等距（isometric）SVG 技术图，不是视频。** 图可以点、可以悬停、有动画，面向"原理科普"。

| | anatomy | 我们 |
|---|---|---|
| 产物 | 交互式 SVG 图 | 视频（逐帧） |
| 画面对象 | 机器、仪器、工具 | 手机、门、床、手 |
| 复杂度 | 一个 Figure 40-80 个零件，Hero 80-150，Epic 200+ | 一页 15 秒，零件要少 |
| 技术栈 | TypeScript + SVG + WebGL | Canvas 2D + 渲染管线 |
| 验证 | 几何审计 + 放大看 | 还要管"动得好不好" |

**不能照搬**：它的 `kit/iso-kit.ts`（等距渲染套件）、零件词汇（导轨、法兰、卡箍）—— 那是给机器画的。
**能照搬**：验证方法论、对象思维、反面清单。

## 一、最该抄的一条：Measure, then look（先量，再看）

它的工作方式里有两条**确定性检查**，跑不过不许交付：

```sh
node build.mjs --audit        # 必须打印 audit passed，每一项失败计数为 0
node scripts/lines.mjs page.html   # 必须打印 line ends: 0
```

审计项包括：不穿透、每个端点落在真实接合处、没有悬空的线、管道不折、自重叠、
拥挤度、曲率不抖、遮挡顺序正确。而且**专门防"骗过审计"**：`coverage` 检查记录的
形状是否覆盖 ≥60% 的实际绘制。

它的原话（最重要的一句）：

> **Fixing one close-up by eye.** Tuning a painter's key or nudging a waypoint until one
> screenshot looks right breaks another frame or another theme. The Raptor's hand-set keys
> looked right at 1× and **had 323 depth-order problems**. **Measure, then look.**

**对我们的意义**：我现在验证画质**只有模型看图**（导演回路），上一轮已经撞到
"同一个模型，一次改好一次改坏"。**缺一条确定性的腿。**

可以立刻写的检查（对情感视频同样有效）：

| 检查 | 查什么 | 我们已经撞到过的例子 |
|---|---|---|
| 色板越界 | 渲出来的帧里，色板外的颜色占多少像素 | 高光用了未登记的白色 |
| 形状越界 | 形状有没有画到轮廓外面 | 「沙堆压过玻璃内壁」「高光跑到轮廓外」 |
| 主体占比 | 主体占画面多少 | 评审原话「沙漏只占画幅宽度约 36%」 |
| 帧差 | 连续两帧差异太小 = 画面死了 | 桌面上那几撮散沙三帧没动 |
| 确定性 | 代码里有没有 `Math.random()` | 会破坏"同一时刻渲两次逐像素一致" |
| 相同帧 | 有没有连续 N 帧完全一样 | 静止镜头 vs 卡住 |

这六条**都可以写成脚本**，比模型看图可靠，而且能进渲染管线当门禁。

## 二、对象即解释（The object is the explanation）

> **The object is the explanation.** Don't draw boxes, arrows and labels.
> Invent a real, well-made physical thing whose working *is* the concept.

它的映射表：

| 概念 | 物 |
|---|---|
| 一个共享的 GPU 上下文服务多画布 | 龙门绘图仪：一个打印头访问 16 个井 |
| 缓存键跳过无变化的计算 | 弹子锁：所有销对齐时锁芯转动，什么都不重画 |
| 七个不同字节数的渲染目标 | 七层抽屉的柜子，每层和它的字节数一样深 |
| 可分离模糊（49×49 vs 49+49） | 一块钉板压印，旁边导轨上两把梳子 |

两种失败模式，它说得很准：

> - **Too abstract.** Stacked plates, floating slabs or labelled boxes don't read as anything.
> - **Too flat and bland.** One big slab with a few lines on it has no volume, no parts and nothing to discover.

**对情感视频的翻译**：不要画"心、锁、裂缝"这类**符号**，要发明一个真实的物，
**它的运作本身就是那个情感机制**。

可以给切页提示词的映射表：

| 情感概念 | 物 |
|---|---|
| 反复解释却越来越远 | 两个人各拧一个螺丝，越拧越松 |
| 装作没事 | 一盏灯下，影子比人先动 |
| 两边都想要 | 一只手同时拉两根绳子，越拉越紧 |
| 消耗 | 沙漏（已在用） |
| 说不出口 | 一根线从喉咙里拉出来 |
| 试探 | 手指停在门把手上，又松开 |

我们镜头表里现有的对照：
- ✅ 「一只沙漏，细沙一粒粒往下落」—— 真实的物，机制就是"消耗"
- ⚠️ 「屏幕上的一道裂纹」—— 偏符号，不是机制

## 三、反面案例里直接命中的（它列了 14 条被拒绝的做法）

| 它的反面案例 | 我们的对应 |
|---|---|
| **Pipes through pipes** —— 1× 看着还行，业主放大就发现线穿过了主体，原话「which makes no sense」 | 我们的「沙堆压过玻璃内壁」「高光跑到轮廓外」是同一类：**1× 看不出，放大就坏** |
| **Fixing one close-up by eye** —— 靠眼睛调一个特写，会破坏别的帧 | 导演回路目前就是这样：靠模型看 3 张图拍板 |
| **Lines that stop in mid-air** —— 每条线都要落在东西上 | 可以做确定性检查 |
| **Textures that stop** —— 纹理要么跑到边缘要么淡出，不能中途停 | 我们的线条/图案同理 |
| **Abstract stacks** —— 浮动板块代表"层" | 情感画面不要用抽象符号 |
| **One big plain slab** —— 大平面加几条线太空 | 正好对应「主体只占 36%、四角空」 |
| **Stand-in shapes** —— 为了骗过审计而记录假形状 | 提醒我们：检查本身也可能被绕过 |
| **Colour everywhere** —— 保持单色，除非颜色本身是主题 | 和上游色板规则一致 |

## 四、它的验收清单（可以改成我们的）

分八块，其中几条可以直接变成我们的数字：

- **Composition**：主体居中，占卡片 **55–65%**
  → 我们的评审说「沙漏只占 36%」，**正好对上这个标准**。这个数字可以直接写进评审提示词。
- **Lines**：4× 放大下，每条线都要落在面、另一条线或端点圆点上
- **Tones**：底 `lo`、结构 `mid`、主体 `hi`，**恰好一个** `lit` 强调
- **Text in the drawing**：图里最多一个刻字标签，其余都在卡片角落/图例
- **Motion**：缓动、不跳、空闲有巡航、离屏停止、减少动效下静止

## 五、它的尺度分档（值得学的工作方式）

先定尺寸，再动手，而且按尺寸决定投入：

- **Figure**：一个机制，40-80 个零件，**不问直接做**，一般不报时间（常常不到一小时）
- **Hero**：密集对象，80-150 个零件，约 2-4 小时，报时间然后做
- **Epic**：整车/整厂，6 小时以上，**不许直接开始**，给估算 + 提一个保留核心的 Hero 版本

对应我们：
- 一页 = Figure
- 一页 + 导演回路 = Hero
- 整片 = Epic

**「不许直接开始 Epic」这条值得抄**：整片级的操作（比如一次重画 20 页）应该先给估算。

---

## 六、结论：对我们最值钱的三条

1. **补一条确定性的腿。** 现在只有"模型看图"，要加上"脚本量数"。
   先写六项检查：色板越界、形状越界、主体占比、帧差、确定性、相同帧。
2. **把"情感概念 → 物"的映射写进切页提示词。** 不要符号，要机制。
3. **把"主体占 55-65%"这个数字写进评审提示词。** 现在评审能看出"太小了"但没有标尺。
